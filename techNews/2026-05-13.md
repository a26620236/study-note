### Repeating Square Dot Backgrounds in CSS — One `conic-gradient` Does It
### CSS 做重複方點底紋 — 用一個 `conic-gradient` 搞定

[原文連結](https://frontendmasters.com/blog/repeating-square-dots-backgrounds-in-css/)

- **Core trick**
  - Set a small `background-size` (e.g. 100px × 100px) so the pattern tiles automatically.
  - Use `conic-gradient` with hard stops to carve one square dot out of each tile:
    ```css
    background-image: conic-gradient(
      from 0deg at 5px 5px,
      transparent 75%, black 75% 100%
    );
    ```
- **Why it's nicer than alternatives**
  - One declaration, no `mask`, no SVG, transparent regions let content underneath show through.
  - Easy to parameterise (CSS custom properties for dot size, gap, colour) — fits design tokens.
-------
- **核心技巧**
  - 設一個小的 `background-size`（例如 100px × 100px）讓圖樣自動 tile。
  - 用 `conic-gradient` 配硬色階從每個 tile 切出一個方點：
    ```css
    background-image: conic-gradient(
      from 0deg at 5px 5px,
      transparent 75%, black 75% 100%
    );
    ```
- **比其他做法好在哪**
  - 一條宣告搞定、不用 `mask`、不用 SVG，透明區還能讓底層內容透出來。
  - 易參數化（用 CSS custom property 控點大小、間距、顏色）— 接 design token 順手。

### DuckDB Ships Quack: A Client-Server Protocol over HTTP
### DuckDB 推出 Quack：基於 HTTP 的 client-server 協議

[原文連結](https://duckdb.org/2026/05/12/quack-remote-protocol)

- **What it is**
  - Quack lets multiple DuckDB instances talk to each other remotely — first-class client-server setup with multiple concurrent writers.
- **Design choices**
  - Built on HTTP, not a custom wire — reuses proven web infra.
  - Single round-trip per small query, unlike Arrow Flight SQL which needs at least two.
- **Benchmarks vs Postgres**
  - Bulk transfer: 60M rows in 4.94s vs Postgres 158.37s (~32x).
  - Small writes: 5,434 tx/s vs Postgres 4,320 tx/s at 8 threads.
- **Use cases**
  - Observability data aggregation, dashboard query backends, remote catalog services — places where in-process DuckDB couldn't go before.
-------
- **是什麼**
  - Quack 讓多個 DuckDB instance 跨機器互相溝通 — 首次原生支援 client-server 與多寫入者。
- **設計選擇**
  - 走 HTTP，不另發明 wire 協議 — 直接重用成熟 web 基建。
  - 小查詢只要 1 個 round-trip，相較 Arrow Flight SQL 至少 2 個。
- **與 Postgres 對比**
  - 大量傳輸：6,000 萬列耗時 4.94 秒 vs Postgres 158.37 秒（約 32 倍）。
  - 小寫入：8 thread 下 5,434 tx/s vs Postgres 4,320 tx/s。
- **使用情境**
  - 可觀測性資料彙整、dashboard 查詢後端、遠端 catalog 服務 — 過去 in-process DuckDB 進不去的場景。

### Cloudflare's One-Line Fix for QUIC's CUBIC Death Spiral
### Cloudflare 一行修補 QUIC 上 CUBIC 的「死亡循環」

[原文連結](https://blog.cloudflare.com/quic-death-spiral-fix/)

- **The bug**
  - After packet loss, CUBIC's congestion window got pinned at the minimum (2 packets) and never recovered — even when the network cleared up.
- **The death spiral**
  - 2-packet burst sent → ACKed after ~14ms (RTT) → `bytes_in_flight` drops to zero → algorithm misinterprets full RTT as idle → recovery boundary advances → false recovery state → window growth skipped → repeat ~999 times in 6.7s.
- **The fix**
  - Track most-recent ACK timestamp; measure idle duration from `max(last_ack_time, last_sent_time)` instead of just `last_sent_time`.
  - Basically one line of logic; 100% test pass-rate restored.
- **Why it matters for everyone**
  - This affects any QUIC stack using CUBIC under loss — fast-moving spec, easy to inherit subtle bugs from BSD/TCP heritage.
-------
- **Bug 是什麼**
  - 一發生 packet loss，CUBIC 的擁塞窗就被卡在最小值（2 packets），即使網路恢復也不會回升。
- **死亡循環的步驟**
  - 送 2 packet 突發 → 約 14ms（RTT）後收到 ACK → `bytes_in_flight` 歸零 → 演算法把整個 RTT 當 idle → recovery 邊界往前推 → 偽造的 recovery 狀態 → 跳過視窗成長 → 6.7 秒內重複約 999 次。
- **修補**
  - 紀錄最近一次 ACK 時間；idle 期改從 `max(last_ack_time, last_sent_time)` 起算，而非只看 `last_sent_time`。
  - 邏輯實際只一行；測試通過率恢復 100%。
- **為什麼大家都該看**
  - 任何在 loss 下用 CUBIC 的 QUIC stack 都會中 — 這支規格走得快，從 BSD／TCP 繼承的細微 bug 很容易跟著進來。

### Exim RCE CVE-2026-45185: Unauthenticated Use-After-Free in TLS/BDAT
### Exim RCE CVE-2026-45185：TLS／BDAT 路徑的未授權 use-after-free

[原文連結](https://xbow.com/blog/dead-letter-cve-2026-45185-xbow-found-rce-exim)

- **The flaw**
  - When a GnuTLS-protected SMTP session closes, the transfer buffer is freed; a nested BDAT receive wrapper then calls `ungetc()`, writing one newline into the freed region.
  - That single write corrupts allocator metadata enough to escalate to unauthenticated RCE.
- **Affected**
  - Exim 4.97 as shipped on Debian/Ubuntu (including Ubuntu 24.04 LTS) with GnuTLS — i.e. distro defaults.
- **Status**
  - Reported May 1, private fix confirmed May 5, coordinated public disclosure May 12.
- **Action**
  - Apply distro updates today; if you can't, switch the TLS library off GnuTLS or restrict who can reach port 25 / 465 / 587.
-------
- **漏洞本身**
  - GnuTLS 保護的 SMTP session 關閉時，傳輸 buffer 已被釋放；接著巢狀的 BDAT receive wrapper 仍呼叫 `ungetc()`，往已釋放的記憶體寫一個換行字元。
  - 這一個位元組的寫入就足以破壞 allocator 的元資料，升級成未授權 RCE。
- **受影響**
  - Debian／Ubuntu（含 Ubuntu 24.04 LTS）預設 GnuTLS 配置下的 Exim 4.97 — 也就是發行版預設安裝。
- **時程**
  - 5/1 通報、5/5 確認私下修補、5/12 跨發行版協同公開。
- **應對**
  - 立即套用發行版更新；若做不到，把 TLS library 從 GnuTLS 切走，或限制 25／465／587 port 的可達 IP。

## Glossary

- **MCP server**
  - A server that exposes tools, resources, or prompts to LLM agents over the Model Context Protocol — standardised way for agents to call external systems.
  - 透過 Model Context Protocol 把工具、資源、prompt 暴露給 LLM agent 的伺服器 — agent 呼叫外部系統的標準介面。
- **LongMemEval**
  - A benchmark suite for evaluating long-term memory in LLM agents — measures retrieval of facts mentioned in distant past conversations.
  - 一套評估 LLM agent 長期記憶的 benchmark — 衡量能否準確找回久遠對話中提到的事實。
- **R@5 (recall at 5)**
  - Retrieval-quality metric: fraction of questions where the correct piece of memory appears in the top-5 retrieved results.
  - 檢索品質指標：正確答案出現在 top-5 結果中的比例。
- **CUBIC**
  - The default TCP congestion-control algorithm in Linux since 2007; QUIC stacks often reuse it. Adjusts the congestion window using a cubic function of time since the last congestion event.
  - Linux 自 2007 年起的預設 TCP 擁塞控制演算法；QUIC stack 常直接沿用。用「自上次擁塞以來的時間」之三次函數來調整擁塞窗。
- **Congestion window (cwnd)**
  - The amount of unacknowledged data the sender allows to be in flight at once — congestion control adjusts this to balance throughput against loss.
  - 發送方允許「同時在飛行中、尚未被 ACK」的資料量上限 — 擁塞控制透過調整它在吞吐量與遺失之間取得平衡。
- **`bytes_in_flight`**
  - The runtime counter of how many bytes the sender has sent but not yet had acknowledged — central to most congestion-control logic.
  - 發送端「已送出但尚未收到 ACK」的位元組數量 runtime 計數器 — 多數擁塞控制邏輯的核心狀態。
- **Use-after-free (UAF)**
  - A memory-safety bug where memory is accessed after being freed; commonly exploited by overlapping a freed allocation with attacker-controlled state.
  - 記憶體已釋放仍被存取的記憶體安全 bug；常見的 exploit 手法是讓攻擊者控制的內容剛好覆蓋到那塊已釋放區域。
- **BDAT (SMTP)**
  - An SMTP extension (CHUNKING) that sends message body in length-prefixed chunks instead of the legacy DATA `.\r\n` terminator — relevant to Exim's CVE today.
  - SMTP 的擴充指令（CHUNKING），用「長度前綴的 chunk」傳訊息本文，取代傳統 DATA 命令的 `.\r\n` 結尾 — 與今日 Exim 的 CVE 直接相關。
- **Function calling**
  - The pattern where an LLM emits a structured tool call (name + JSON args) instead of plain text — the host then executes the tool and feeds results back.
  - LLM 不輸出純文字、而是輸出結構化的工具呼叫（工具名 + JSON 參數）的模式 — 由 host 執行工具後把結果回灌給模型。
- **Distillation**
  - Training a smaller "student" model to mimic the outputs of a larger "teacher" — used here to compress Gemini 3.1's tool-calling behaviour into 26M parameters.
  - 訓練較小的「student」模型去模仿較大「teacher」模型的輸出 — Needle 用這方法把 Gemini 3.1 的工具呼叫能力壓到 26M 參數。
