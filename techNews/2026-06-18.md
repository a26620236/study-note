### Anthropic: How We Contain Claude Across Products
### Anthropic：我們如何在各產品中「圈住」Claude

[原文連結](https://www.anthropic.com/engineering/how-we-contain-claude)

- **Core**
  - The post tackles "blast radius" — limiting what an agent can damage — across claude.ai, Claude Code, and Cowork, and argues environment-layer containment (sandboxes, VMs, filesystem boundaries, egress controls) is the only defense that holds when attackers control the input.
  - Model-layer defenses (system prompts, classifiers) are probabilistic: Opus 4.7 holds prompt-injection success to ~0.1% on single attempts, but that's not zero, so it can't be the last line.
- **Three isolation patterns**
  - claude.ai uses ephemeral gVisor containers; Claude Code uses a human-in-the-loop OS sandbox (Seatbelt / bubblewrap) on the user's machine; Cowork uses a full VM with its own kernel.
  - Claude Code's new auto mode reduces approval prompts by 84% and catches ~83% of risky actions before execution — a direct fix for the "93% blind approval" fatigue users showed.
- **Hard-won lessons**
  - An internal phishing test exfiltrated AWS credentials 24 out of 25 times via innocent-looking prompts; only egress controls stopped it.
  - Mature tools (hypervisors, seccomp) beat Anthropic's own custom proxies and classifiers — distrust homegrown security components.
-------
- **核心**
  - 文章談的是「blast radius（波及範圍）」—— 限制一個 agent 能造成多大破壞 —— 涵蓋 claude.ai、Claude Code 與 Cowork，並主張環境層圈住（沙箱、VM、檔案系統邊界、egress 控制）是當攻擊者能控制輸入時唯一站得住腳的防線。
  - 模型層防禦（system prompt、分類器）是機率性的：Opus 4.7 把單次 prompt injection 的成功率壓到約 0.1%，但那不是零，所以不能當最後一道防線。
- **三種隔離模式**
  - claude.ai 用短生命週期的 gVisor 容器；Claude Code 在使用者機器上用人類在迴路中的 OS 沙箱（Seatbelt／bubblewrap）；Cowork 用擁有獨立 kernel 的完整 VM。

-------
- **核心**
  - Alex Ellis 主張那道窄窄的 benchmark 差距（SWE-Bench 上 Qwen 27B 77.2% vs Opus 88.6%）掩蓋了真正的差異：前沿模型（0.5–2 兆參數）能無人看管穩定工作數小時；27B 本地模型需要監督。

### Builder.io: How to Make AI Agents Follow Your Design System
### Builder.io：如何讓 AI agent 遵守你的 Design System

[原文連結](https://www.builder.io/blog/how-to-make-ai-agents-follow-your-design-system)

- **Core**
  - Agents learn from your codebase, not your docs — "your codebase is your prompt." They replicate patterns they see in production, even deprecated ones, over instructions in markdown files.
- **Techniques**
  - Enforce in code, not rules: ESLint rules that ban legacy imports (the error message becomes the prompt), stricter lint for agents than humans.
  - Use TypeScript discriminated unions so invalid prop combinations are compile errors the agent fixes in its own loop; use Stylelint `stylelint-declaration-strict-value` to force design tokens over raw hex.
  - Keep a `src/design-system/examples/` directory of golden, compilable references — copying known-good templates is "the one thing these models do almost perfectly."
- **Verification loop**
  - Before opening a PR, agents run tsc + ESLint + Stylelint + Storybook interaction tests, so mechanical issues fail locally and reviewers focus on real design decisions.
-------
- **核心**
  - Agent 是從你的 codebase 學、而不是從你的文件學 ——「你的 codebase 就是你的 prompt」。它們會複製在正式碼裡看到的模式（連已棄用的也照抄），勝過 markdown 檔裡的指示。
- **手法**
  - 用程式碼強制、別用規則檔：用 ESLint 規則封鎖 legacy import（錯誤訊息本身就變成 prompt），給 agent 比人類更嚴格的 lint。
  - 用 TypeScript discriminated union，讓不合法的 prop 組合變成編譯錯誤，agent 在自己的迴圈裡就會修；用 Stylelint 的 `stylelint-declaration-strict-value` 強制使用 design token，而非裸的 hex 色碼。
  - 維護一個 `src/design-system/examples/` 黃金可編譯範例目錄 —— 複製已知良好的範本是「這些模型幾乎做得完美的一件事」。
- **驗證迴圈**
  - 開 PR 前，agent 先跑 tsc + ESLint + Stylelint + Storybook 互動測試，讓機械性問題在本地就失敗，reviewer 才能專注在真正的設計決策。

### Demystifying the View Transition Pseudo Tree
### 拆解 View Transition 的 Pseudo 元素樹

[原文連結](https://master.dev/blog/demystifying-the-view-transition-pseudo-tree/)

- **Core**
  - When a view transition fires, the browser builds a pseudo-element tree: `::view-transition` → `::view-transition-group(name)` → `::view-transition-image-pair(name)` → `::view-transition-old(name)` + `::view-transition-new(name)`.
  - `-group` animates position/size/rotation via matrix transforms; `-image-pair` isolates a stacking context; `-old`/`-new` are the before/after snapshots that cross-fade by default.
- **Takeaways**
  - Set `animation-duration`, `animation-delay`, and `animation-timing-function` separately rather than the `animation` shorthand, so you don't wipe out the browser's default fade.
  - Add `view-transition-name` strategically to pull elements out of the root transition for granular control; animation props set on a group cascade to children.
-------
- **核心**
  - 當 view transition 觸發時，瀏覽器會建出一棵 pseudo 元素樹：`::view-transition` → `::view-transition-group(name)` → `::view-transition-image-pair(name)` → `::view-transition-old(name)` + `::view-transition-new(name)`。
  - `-group` 用 matrix transform 動畫處理位置／大小／旋轉；`-image-pair` 隔離出一個 stacking context；`-old`／`-new` 是前後快照，預設會交叉淡入淡出。
- **重點**
  - 分開設定 `animation-duration`、`animation-delay`、`animation-timing-function`，別用 `animation` 簡寫，免得把瀏覽器預設的淡入淡出清掉。
  - 策略性地加 `view-transition-name`，把元素從 root transition 拉出來做細緻控制；設在 group 上的動畫屬性會往子元素 cascade。

### Tailwind CSS 4: Why Utility Classes Scale Better Than Semantic CSS
### Tailwind CSS 4：為何 utility class 比語意化 CSS 更好擴展

[原文連結](https://dev.to/cathylai/tailwind-css4-why-those-inline-styles-are-actually-more-scalable-a-senior-css-developers-guide-hdj)

- **Core**
  - The argument: utility classes look like inline styles but scale better because the CSS bundle stays constant — "whether you have 10 pages or 10,000 pages, your production CSS stays virtually the same size."
  - Traditional semantic CSS rots: fearing unknown dependencies, devs duplicate (`.card-variant-3`, `.card-variant-3-updated`) instead of refactoring, and orphaned rules linger forever.
- **Trade-offs**
  - Utility classes trade dense markup during development for low refactor risk and self-cleaning styles (delete the component, delete its styles); encapsulating them inside components like `<Card variant="premium">` hides the verbose class soup.
  - Counterpoint from comments: disciplined semantic CSS avoids these issues, and 15 classes on one element still obscures intent — so this assumes component architecture and team discipline.
-------
- **核心**
  - 論點是：utility class 看起來像 inline style，但更好擴展，因為 CSS bundle 大小維持恆定 ——「不管你有 10 頁還是 10,000 頁，正式環境的 CSS 大小幾乎不變。」
  - 傳統語意化 CSS 會腐爛：因為怕動到未知相依，開發者寧可複製（`.card-variant-3`、`.card-variant-3-updated`）也不重構，孤兒規則永遠留著。
- **取捨**
  - utility class 拿「開發時擁擠的 markup」換來「低重構風險」與「自我清理的樣式」（刪掉元件就刪掉它的樣式）；把它們封裝進像 `<Card variant="premium">` 的元件裡，就能藏起那一長串 class。
  - 留言區反論：紀律良好的語意化 CSS 不會有這些問題，而且單一元素塞 15 個 class 一樣難讀懂意圖 —— 所以這套說法的前提是元件化架構＋團隊紀律。

### RFC 10008: The New HTTP QUERY Method
### RFC 10008：全新的 HTTP QUERY 方法

[原文連結](https://www.rfc-editor.org/info/rfc10008/)

- **Core**
  - QUERY is a new HTTP method that processes an enclosed request body "in a safe and idempotent manner" and returns results — combining POST-like bodies with GET-like guarantees.
  - It fills the gap where GET breaks on oversized query strings (URI limits, encoding, logging) and POST gives no safe/idempotent signal (blocking caching and auto-retry).
- **Impact on API design**
  - Send complex queries (SQL, JSONPath, XSLT) as a request body while still allowing caching and automatic retries; results can get a URI via `Content-Location`/`Location` for follow-up GETs; supports conditional requests with ETags.
-------
- **核心**
  - QUERY 是新的 HTTP 方法，會以「安全且冪等的方式」處理請求 body 並回傳結果 —— 把 POST 般的 body 與 GET 般的保證結合起來。
  - 它補上一個缺口：GET 在查詢字串過大時會出問題（URI 長度限制、編碼、log），而 POST 又不帶安全／冪等的語意（讓 caching 與自動重試難以運作）。
- **對 API 設計的影響**
  - 可把複雜查詢（SQL、JSONPath、XSLT）放進請求 body，同時仍允許 caching 與自動重試；查詢結果可透過 `Content-Location`／`Location` 取得 URI 供後續 GET；並支援以 ETag 做條件式請求。

### Running Firecracker microVMs Inside EC2 to Start Browsers in <1s
### 在 EC2 內跑 Firecracker microVM，1 秒內啟動瀏覽器

[原文連結](https://browser-use.com/posts/firecracker-browser-infra)

- **Core**
  - Browser Use Cloud runs Firecracker microVMs inside ordinary EC2 instances ("VMs inside VMs"); each browser session gets an isolated microVM that starts in <400ms at $0.02/hour (down from $0.06).
  - They migrated off Unikraft unikernels, which needed manual tuning during spikes and once took production down for 45 minutes.
- **Details**
  - Memory: switching from 4KB to 2MB pages plus custom `userfaultfd` page-fault handling cut VM resume time from 9.8s to 3.1s and page faults by 91%.
  - CPU: browsers launch with unpinned vCPUs then pin to stable cores; both hyperthread siblings per browser plus real-time priority eliminated 17% session loss.
  - Result: end-to-end browser creation is 825ms p50 / 1.35s p99, with zero failures across a 10,000-session stress test.
-------
- **核心**
  - Browser Use Cloud 在一般 EC2 instance 內跑 Firecracker microVM（「VM 裡的 VM」）；每個瀏覽器 session 拿到一個隔離的 microVM，啟動 <400ms，每小時 0.02 美元（原本 0.06）。
  - 他們從 Unikraft unikernel 遷移過來 —— 後者在流量尖峰時需要人工調整，曾讓正式環境掛掉 45 分鐘。
- **細節**
  - 記憶體：從 4KB 換成 2MB 分頁、加上自製的 `userfaultfd` page fault 處理，把 VM resume 時間從 9.8 秒降到 3.1 秒，page fault 減少 91%。
  - CPU：瀏覽器啟動時不綁定 vCPU，就緒後再 pin 到穩定核心；每個瀏覽器配一對 hyperthread 兄弟核心加上 real-time 優先權，消除了 17% 的 session 流失。
  - 成果：端到端建立瀏覽器 p50 為 825ms、p99 為 1.35 秒，10,000 個 session 壓測零失敗。

### Epic Games Open-Sources Lore, a Content-Addressed VCS for Scale
### Epic Games 開源 Lore：為大規模打造的內容定址版控系統

- **Core**
  - Lore is a centralized, content-addressed version control system from Epic Games, built for repos that mix code with large binary assets (games, film) where Git struggles.

- **Details**
  - Chunked storage splits large files into reusable indexed chunks; sparse workspaces fetch only needed data on demand; a service-backed cache scales throughput for big teams.
  - Immutable, cryptographically signed revision chains; lightweight branches as mutable references; CLI plus SDKs for C/C++, C#, Rust, Go, Python, JavaScript; MIT-licensed.
-------
- **核心**

  - 它在 Merkle tree 中以 content hash 參照資料，讓跨歷史與分支的去重與快速比較成為可能。

## Glossary

- **MCP (Model Context Protocol)**
  - An open protocol that standardizes how LLM agents call external tools and data sources.
  - 標準化 LLM agent 如何呼叫外部工具與資料來源的開放協議。
- **Agent Skills**
  - Reusable, composable bundles of instructions plus scripts that an agent loads on demand, instead of stuffing everything into one system prompt.
  - 可重用、可組合的「指令＋腳本」包，讓 agent 按需載入，而不是把所有東西塞進單一 system prompt。
- **Prompt Injection**
  - An attack where malicious text in tool output or web content hijacks an agent into following the attacker's instructions.
  - 一種攻擊：工具輸出或網頁內容中的惡意文字劫持 agent，使其改去遵循攻擊者的指令。
- **Egress Control**
  - Network rules that restrict what destinations a sandboxed agent can send data to — the key defense against exfiltration.
  - 限制沙箱化 agent 能把資料送往哪些目的地的網路規則 —— 防止資料外洩的關鍵防線。
- **gVisor**
  - A user-space kernel that sandboxes containers by intercepting syscalls, giving stronger isolation than plain containers.
  - 一個 user-space kernel，透過攔截 syscall 來沙箱化容器，提供比一般容器更強的隔離。
- **HTTP QUERY Method**
  - A new HTTP method that carries a request body like POST but is safe and idempotent like GET, for query-heavy APIs.
  - 一個新的 HTTP 方法，像 POST 一樣帶請求 body，卻像 GET 一樣安全且冪等，適合查詢密集的 API。
- **Idempotent**
  - An operation that produces the same result whether called once or many times, making safe to auto-retry.
  - 不論呼叫一次或多次都得到相同結果的操作，因此可以安全地自動重試。
- **View Transitions API**
  - A browser API that animates between two DOM states by snapshotting old/new views and cross-fading them via generated pseudo-elements.
  - 一套瀏覽器 API，透過對舊／新畫面拍快照並用生成的 pseudo 元素交叉淡入淡出，來為兩個 DOM 狀態之間做動畫。
- **Design Token**
  - A named, reusable value (color, spacing, radius) that encodes a design decision, used instead of raw hardcoded values.
  - 一個有名稱、可重用的值（顏色、間距、圓角），把設計決策編碼起來，用來取代寫死的裸值。
- **Discriminated Union (TypeScript)**
  - A union of types sharing a literal "tag" field, letting the compiler reject invalid property combinations.
  - 共用一個字面量「標籤」欄位的型別聯集，讓編譯器能拒絕不合法的屬性組合。
- **Firecracker microVM**
  - A lightweight virtual machine (by AWS) that boots in milliseconds with minimal overhead, used for strong per-task isolation.
  - AWS 推出的輕量虛擬機，毫秒級開機、額外負擔極小，用於對每個任務做強隔離。
- **Content-Addressed Storage**
  - Storage that identifies data by the hash of its content (not a path), enabling deduplication and tamper-evident history.
  - 以「內容的雜湊值」而非路徑來識別資料的儲存方式，可去重並讓歷史具防竄改性。
- **tree-sitter**
  - A fast incremental parser that builds concrete syntax trees, widely used to give tools structural understanding of source code.
  - 一個快速的增量解析器，可建立具體語法樹，被廣泛用來讓工具理解原始碼的結構。
