### `claude-hook-utils`: Pythonic Building Blocks for Claude Code Hooks
### `claude-hook-utils`：Pythonic 的 Claude Code hook 工具箱

[GitHub 連結](https://github.com/RasmusGodske/claude-hook-utils)

- **What it solves**
  - Stops you from hand-rolling JSON parsing, response formatting, and error handling for every hook script.
- **Core APIs**
  - `HookHandler` base class — override the hooks you actually need (`PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `SessionStart`).
  - Typed `PreToolUseInput`, `PreToolUseResponse` with `.allow()` / `.deny()` / `.ask()` builders.
  - `file_path_matches(*globs)` — glob check on tool inputs.
  - `HookLogger` — namespace-organised JSONL logging.
- **Usage**
  - ```python
    class MyValidator(HookHandler):
        def pre_tool_use(self, input: PreToolUseInput) -> PreToolUseResponse | None:
            return PreToolUseResponse.allow()
    ```
  - Wire it up in `.claude/settings.json`.
- **Install**
  - `pip install claude-hook-utils`. MIT, current `v0.4.0`.
-------
- **要解決什麼**
  - 不用每寫一個 hook 都手動處理 JSON 解析、回應格式、錯誤處理。
- **主要 API**
  - `HookHandler` 基底類 — 只 override 你需要的 hook（`PreToolUse`、`PostToolUse`、`UserPromptSubmit`、`SessionStart`）。
  - 帶型別的 `PreToolUseInput`、`PreToolUseResponse`，附 `.allow()` / `.deny()` / `.ask()` builder。
  - `file_path_matches(*globs)` — 對 tool 輸入做 glob 檢查。
  - `HookLogger` — 依 namespace 整理的 JSONL log。
- **使用方式**
  - ```python
    class MyValidator(HookHandler):
        def pre_tool_use(self, input: PreToolUseInput) -> PreToolUseResponse | None:
            return PreToolUseResponse.allow()
    ```
  - 在 `.claude/settings.json` 接上去。
- **安裝**
  - `pip install claude-hook-utils`。MIT 授權，目前版本 `v0.4.0`。

### AI Agent Failure Modes Beyond Hallucination
### 比幻覺更難搞的 AI agent 失敗模式

[原文連結](https://dev.to/maximsaplin/ai-agent-failure-modes-beyond-hallucination-208g)

- **The taxonomy (selected)**
  - **Context & memory**: cold-start amnesia, working-memory rot, lossy compaction.
  - **Task completion**: one-shotting (burns context, leaves task half-done), progress-as-completion, false E2E pass (unit tests green, real flow broken).
  - **Output quality**: ugly wish-granting (literal interpretation of loose spec), over-engineering by default, default-fill slop, spec-deliverable confusion.
  - **Architecture**: summary-only handoff loss, async reconciliation failure, hidden harness control, plan drag (rigid plans resist mid-course correction).
- **Recursive cost drift**
  - Orchestrator-worker patterns can quietly burn **10–50× expected budget** by spawning sub-agents — invisible until the bill arrives.
- **Mitigation pattern**
  - "Every fix is a structural constraint, not a better prompt."
  - Explicit `PROJECT_STATE.md` files defeat cold-start amnesia.
  - Verification gates: require logs / screenshots / curl output before "done".
  - Hard token caps with fallback to smaller models mid-execution.
  - Separate auditor sessions for review — never self-review.
- **Why read it**
  - The most complete catalog so far of "the bugs you only see at scale" — useful as a checklist when designing an agent system.
-------
- **分類（節錄）**
  - **Context 與記憶**：冷啟動失憶、working memory 腐爛、有損壓縮。
  - **任務完成**：one-shotting（一口氣燒完 context，事情做一半）、把進度當完成、假 E2E 過關（單元測試綠了但實際流程壞了）。
  - **輸出品質**：醜版「願望成真」（照字面解析模糊 spec）、預設過度設計、用訓練語料的平庸預設值填空、把 spec 跟交付物混在一起。
  - **架構**：摘要交接遺失、非同步合流失敗、harness 暗中改 prompt、計畫拖累（僵化的計畫無法在中途調整）。
- **遞迴成本漂移**
  - orchestrator-worker 模式可悄悄燒掉預算的 **10–50 倍** — 因為一直生 sub-agent，帳單來了才發現。
- **修補模式**
  - 「每個修補都是結構性約束，不是更好的 prompt。」
  - 用明確的 `PROJECT_STATE.md` 治冷啟動失憶。
  - 驗證閘門：完成前要附 log／截圖／curl 輸出。
  - 硬性 token 上限，超過就降到小模型。
  - 用獨立的 auditor session 做 review — 不要自己審自己。
- **為什麼讀**
  - 目前最完整的「規模化後才會冒出來的 bug」清單 — 設計 agent 系統時當 checklist 用很值得。

### Builder.io: The Best Agent-Native Apps Use Less AI
### Builder.io：好的 agent-native app 要用更少 AI

[原文連結](https://www.builder.io/blog/why-the-best-agent-native-apps-use-less-ai)

- **The thesis**
  - "The mark of a great agent-native application is what it **doesn't** send to the model." Burning a frontier model on deterministic work is architectural failure.
- **The 400-byte JSON anecdote**
  - Author Matt Abrams sent a 400-byte JSON string to a frontier model: 50 seconds, ~50,000 tokens, real $$. `JSON.parse()` in <1ms with zero cost.
- **Three-surface model**
  - **Surface 1 — UI**: fast, fixed (buttons / forms).
  - **Surface 2 — Agent + LLM**: flexible, expensive.
  - **Surface 3 — Actions**: reusable code snippets authored at runtime, callable by both UI and agent.
- **"Crystallization"**
  - When the agent does the same deterministic thing repeatedly, promote it to a fast/cheap Action — pull it *out* of the inference layer. Over time the LLM is reserved only for genuinely fuzzy work.
-------
- **核心論點**
  - 「好的 agent-native app，看的是它**沒**丟給模型的部分。」把確定性的工作丟給 frontier 模型，是架構失敗。
- **400 bytes 的 JSON 故事**
  - 作者 Matt Abrams 把 400 bytes 的 JSON 丟給前沿模型：燒掉 50 秒、~50,000 tokens、真金白銀。`JSON.parse()` <1ms、0 成本。
- **三層介面模型**
  - **第一層 — UI**：快、固定（按鈕／表單）。
  - **第二層 — Agent + LLM**：彈性、昂貴。
  - **第三層 — Actions**：執行期生成的可重用 code snippet，UI 與 agent 都能呼叫。
- **「crystallization（結晶化）」**
  - 當 agent 重複做同一件確定性事情時，就把它「結晶」成快又便宜的 Action，從推理層中**拉出來**。長期下來，模型只保留給真正模糊的任務。

### DBOS: Postgres Is All You Need for Durable Execution
### DBOS：Postgres 就夠做 durable execution

[原文連結](https://www.dbos.dev/blog/postgres-is-all-you-need-for-durable-execution)

- **Durable execution recap**
  - Checkpoint a program's progress to a database so a crash can resume from the last checkpoint — "save points" for backend workflows.
- **The DBOS take**
  - Separate orchestrators (Temporal, Airflow, AWS Step Functions) are unnecessary complexity. If you're checkpointing to a database anyway, **make the database the orchestrator**.
- **Architecture**
  - Clients enqueue workflows by inserting into a Postgres table.
  - App servers poll, dequeue, and run.
  - Step outputs are checkpointed back to Postgres.
  - DB integrity constraints prevent duplicate execution.
  - Crashed servers' workflows are recovered by other servers — pure Postgres semantics.
- **Side effects**
  - SQL becomes the observability layer for free — complex filters and analytics queries run directly on workflow state.
- **Why it lands now**
  - Postgres 17/18 logical replication and durable subscriptions make the "DB as orchestrator" pattern much more credible than five years ago.
-------
- **Durable execution 一句話**
  - 把程式進度 checkpoint 到資料庫，crash 後從上一個 checkpoint 接著跑 — 後端 workflow 的「存檔點」。
- **DBOS 的主張**
  - 像 Temporal、Airflow、AWS Step Functions 這種「獨立 orchestrator」是多餘的複雜度。既然反正要 checkpoint 到資料庫，**那就讓資料庫當 orchestrator**。
- **架構**
  - Client 用「插入 Postgres table」這個動作把 workflow 入列。
  - App server 去 poll、dequeue、執行。
  - 每一步的輸出回寫到 Postgres 當 checkpoint。
  - 資料庫的完整性約束擋掉重複執行。
  - Crash 的伺服器留下的 workflow 由其他伺服器接手 — 純 Postgres 語意。
- **附帶效果**
  - SQL 直接變成 observability 層 — 複雜過濾與分析查詢可直接打 workflow 狀態。
- **為什麼現在站得住**
  - Postgres 17／18 的邏輯複寫與 durable subscription，讓「DB 當 orchestrator」這個模式比五年前可信得多。

## Glossary

- **Dynamic workflows (Claude Code)**
  - The Opus 4.8 research-preview feature that runs hundreds of parallel sub-agents in a single Claude Code session — designed for migrations across very large codebases.
  - Opus 4.8 的研究預覽功能，可在單一 Claude Code session 內平行跑數百個 sub-agent — 為「跨大型 codebase 的遷移」設計。
- **Effort control**
  - A user-selectable knob (`high` / `extra` / `max`) on Claude.ai and Cowork that decides how much reasoning the model does before answering — trades latency / cost for depth.
  - 在 Claude.ai 與 Cowork 上可選的旋鈕（`high` / `extra` / `max`），決定模型回答前要思考多深 — 用延遲／成本換深度。
- **YOLO Classifier**
  - The internal Claude Code name for the auto-mode permission classifier — it decides whether a tool call is safe enough to skip the human approval dialog.
  - Claude Code 內部對 auto mode 權限分類器的命名 — 它決定一次 tool call 安不安全到可以跳過人工確認對話框。
- **`autoMemoryEnabled` / `autoDreamEnabled`**
  - Undocumented Claude Code settings toggles for persistent agent memory and background consolidation — Claude Code's experimental self-improvement layer.
  - 沒寫進文件的 Claude Code 設定開關，分別對應持久記憶體與背景整合 — Claude Code 實驗中的自我改善層。
- **Recursive cost drift**
  - The pattern where an orchestrator agent spawns sub-agents that spawn sub-sub-agents, silently multiplying token spend 10–50× the original budget — typically only noticed at billing time.
  - 一種 agent 失敗模式：orchestrator 一直派生 sub-agent，sub-agent 又派生 sub-sub-agent，token 花費悄悄變成原預算的 10–50 倍 — 通常要收到帳單才會發現。
- **Crystallization (Builder.io)**
  - The architectural move of "freezing" deterministic work that the agent keeps repeating into a fast, cheap, reusable Action — pulling that path out of the LLM inference layer.
  - 一種架構動作：把 agent 重複做的確定性工作「結晶」成快、便宜、可重用的 Action — 把這條路徑從 LLM 推理層裡拉出來。
- **Three-surface model (Builder.io)**
  - The architecture pattern: Surface 1 = static UI, Surface 2 = agent + LLM, Surface 3 = Actions (callable by both). The agent earns its cost only on Surface 2 work.
  - 一種架構模式：第一層是靜態 UI，第二層是 agent + LLM，第三層是 Actions（兩邊都可呼叫）。agent 只在第二層的工作上才值得它的成本。
- **Durable execution**
  - A pattern where a workflow's progress is regularly checkpointed to a database, so a crash mid-flight resumes from the last checkpoint instead of restarting — the core idea behind Temporal, Step Functions, and now DBOS-on-Postgres.
  - 一種模式：把 workflow 的進度定期 checkpoint 到資料庫，crash 之後從上一個 checkpoint 繼續、不必整個重跑 — 這是 Temporal、Step Functions、現在 DBOS-on-Postgres 共同的核心理念。
- **Compound engineering**
  - A methodology where every unit of work is supposed to make the next unit easier — by writing down learnings, generating reusable skills, and weighting effort heavily toward planning (80%) over execution (20%).
  - 一種方法論：每單位工作都應該讓下一單位更輕鬆 — 靠紀錄學到的東西、產出可重用 skill、把心力大幅押在計畫（80%）而非執行（20%）。
- **Verification gate**
  - A structural constraint in agent design: the agent must produce concrete evidence (logs, screenshots, curl output) before it's allowed to declare a task complete — defeats "progress-as-completion" failure.
  - agent 設計裡的一個結構約束：agent 要拿出具體證據（log、截圖、curl 輸出）才能宣告任務完成 — 用來治「把進度當完成」這個失敗模式。
- **`PROJECT_STATE.md` pattern**
  - A small, explicitly maintained markdown file that captures the agent's working context (decisions, constraints, current focus) — survives across sessions, defeats cold-start amnesia.
  - 一個小型、明確維護的 markdown 檔，紀錄 agent 的工作 context（決策、限制、當前焦點） — 跨 session 存活，治冷啟動失憶。
