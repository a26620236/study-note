### Animating Focus Rings with the View Transitions API
### 用 View Transitions API 動畫化 focus ring

[原文連結](https://frontendmasters.com/blog/animating-focus-with-view-transitions/)

- **Technique**
  - Intercept Tab keypress, then call `document.startViewTransition(() => next.focus())` — the focus shift becomes an automatic animation.
  - Style the focus ring as a child `<span>` with `view-transition-name: focus-ring` so only the ring animates between positions.
- **What it replaces**
  - The old approach of measuring positions with `getBoundingClientRect()` and tweening `top`/`left` in JS — "not particularly performant" in the author's words.
- **Don't forget**
  - Graceful fallback via `if (!document.startViewTransition) return;`.
  - Respect `prefers-reduced-motion` by disabling the animation entirely.
-------
- **技巧**
  - 攔截 Tab 鍵事件，呼叫 `document.startViewTransition(() => next.focus())` — focus 切換就會自動帶動畫。
  - 把 focus ring 做成子 `<span>`，加上 `view-transition-name: focus-ring`，只讓 ring 在位置間動畫。
- **取代了什麼**
  - 過去要 `getBoundingClientRect()` 量位置、再用 JS tween `top`／`left` 的做法 — 作者直言「不太能稱得上效能好」。
- **記得**
  - 要做優雅降級：`if (!document.startViewTransition) return;`。
  - 尊重使用者偏好 `prefers-reduced-motion` 時直接關掉動畫。

### CSS `:nth-child(n of ...)` + `:has()` for Conditional Validation Styling
### CSS `:nth-child(n of ...)` 配 `:has()` 做條件式表單驗證樣式

[原文連結](https://frontendmasters.com/blog/css-n-of-selectors-for-conditional-validation/)

- **What it does**
  - `:nth-child(n of <selector>)` counts only the matching children. Combine it with `:has()` and you can style based on "the Nth field that is filled."
- **Concrete example**
  - "Show success message when at least 3 form fields are filled":
    `:nth-child(3 of .field:has(:where([type="email"],[type="url"],[type="text"]):not(:placeholder-shown), [type="radio"]:checked, option[value=""]:not(:checked)))`
- **Browser caveat (April 2026)**
  - There's a known WebKit bug where state-based styling with this selector may not behave as expected — verify in Firefox during this period.
-------
- **它做什麼**
  - `:nth-child(n of <選擇器>)` 只計算符合的子元素。再配上 `:has()`，就能依「第 N 個被填寫的欄位」來套樣式。
- **具體範例**
  - 「至少填滿 3 個欄位後才顯示成功訊息」：
    `:nth-child(3 of .field:has(:where([type="email"],[type="url"],[type="text"]):not(:placeholder-shown), [type="radio"]:checked, option[value=""]:not(:checked)))`
- **瀏覽器注意（2026/4）**
  - WebKit 目前有個 bug 讓「基於狀態的樣式」搭這個選擇器時行為不如預期 — 這段期間用 Firefox 驗證最穩。

### Introducing TanStack Form
### 認識 TanStack Form

[原文連結](https://frontendmasters.com/blog/introducing-tanstack-form/)

- **What it is**
  - A strongly-typed, headless React form library. Auto-infers types from your form's data structure; you supply the UI.
  - Supports nested fields, arrays, reusable field components, validation on submit/blur/change.
- **What sets it apart**
  - `useStore` and `Subscribe` give reactive references to other field values without prop-drilling.
  - `createFormHookContexts` lets you bake context-aware reusable form components.
- **Position**
  - Article frames it as "detail-oriented, planned for every edge case" — useful when react-hook-form / Formik break down on complex nested or dependent forms.
-------
- **是什麼**
  - 強型別、headless 的 React 表單函式庫。型別會從表單資料結構自動推導；UI 你自己渲染。
  - 支援巢狀欄位、陣列、可重用欄位元件、submit／blur／change 各時機觸發驗證。
- **特色**
  - `useStore`、`Subscribe` 讓你不用 prop drilling 也能拿到其他欄位值的響應式參照。
  - `createFormHookContexts` 可以做出具備 context 感知的可重用表單元件。
- **定位**
  - 文章用「鉅細靡遺、把邊角案例都想過一輪」形容它 — 適合 react-hook-form 或 Formik 在複雜巢狀／依賴表單上開始吃力時。

### Databricks Lakebase: 5x Postgres Write Throughput via Pageserver Image Generation
### Databricks Lakebase：Postgres 寫入吞吐量 5x，秘訣是讓 pageserver 自己生成整頁映像

[原文連結](https://www.databricks.com/blog/how-lakebase-architecture-delivers-5x-faster-postgres-writes)

- **Core change**
  - Traditional Postgres writes full 8KB page images into the WAL after every checkpoint — Full Page Writes (FPW) can inflate WAL volume up to 15x.
  - Lakebase pushes that image generation down to the distributed storage layer. Pageserver only materialises full images when delta records cross a threshold, not on unrelated checkpoint events.
- **Benchmarks**
  - 4.5x throughput gain on 32-vCPU computes (HammerDB TPROC-C), 94% WAL traffic reduction, 2x read tail latency improvement.
  - One customer: ingestion went from 17k to 62k rows/sec.
- **Compatibility**
  - Rolled out globally since late March 2026; reuses the existing `XLOG_FPW_CHANGE` WAL mechanism for seamless rollout without restarts.
- **Take-home**
  - The pattern (push WAL amplification work into storage) is generalisable — worth watching for other managed Postgres vendors to follow.
-------
- **核心變動**
  - 傳統 Postgres 每次 checkpoint 後第一次寫某頁時要把整個 8KB page image 寫進 WAL（Full Page Write），WAL 容量可膨脹到 15 倍。
  - Lakebase 把 image 生成下推到分散式儲存層。Pageserver 只在 delta 累積到門檻時才產生 full image，而非隨意被 checkpoint 觸發。
- **Benchmark**
  - HammerDB TPROC-C 在 32-vCPU 機型上吞吐量 4.5x、WAL 流量降 94%、讀尾延遲 2x 改善。
  - 一位客戶實測：ingest 從 17k 列／秒提升到 62k 列／秒。
- **相容性**
  - 自 2026/3 底全球 rollout；沿用既有的 `XLOG_FPW_CHANGE` WAL 機制，不需重啟即可平滑上線。
- **可借鑑**
  - 「把 WAL 放大工作下推到儲存層」這個模式可推廣 — 值得觀察其他 managed Postgres 廠商會不會跟進。

## Glossary

- **View Transitions API**
  - A browser API that animates the transition between two DOM states automatically — give old/new elements matching `view-transition-name` and the browser tweens between them.
  - 瀏覽器 API，自動為兩個 DOM 狀態之間的切換產生動畫 — 對新舊元素指定相同的 `view-transition-name`，瀏覽器就會自動處理過渡。
- **`:has()` selector**
  - The CSS "parent selector": `el:has(child)` matches `el` only when it contains a matching `child`. Now supported in all major engines.
  - CSS 的「父元素選擇器」：`el:has(child)` 只在 `el` 內含符合條件的 `child` 時才命中。目前主流瀏覽器引擎都已支援。
- **`prefers-reduced-motion`**
  - A media query that tells you the user has asked the OS to minimise non-essential motion — respect it by skipping or simplifying animations.
  - 一個 media query，用來判斷使用者是否在 OS 設定要求減少非必要動畫 — 應對方式是跳過或簡化動畫。
- **Headless library**
  - A library that handles state, logic, and behaviour but leaves the rendering (UI) entirely to you. TanStack Form is headless.
  - 處理狀態、邏輯與行為、但完全把渲染（UI）交給你的函式庫。TanStack Form 屬於這類。
- **Sub-agent**
  - A specialised agent invoked by a primary coding agent for a narrower task (code review, security scan, build-error fixing) — keeps the primary's context window lean.
  - 由主編程 agent 喚起、負責更狹義任務（code review、資安掃描、build 錯誤修復）的專家 agent — 讓主 agent 的 context window 不被佔滿。
- **Continuous batching**
  - An LLM inference technique that lets new requests join an in-flight batch instead of waiting — significantly raises throughput on shared servers.
  - LLM 推理技術，允許新請求加入仍在執行中的批次，而非等待 — 在共用推理伺服器上大幅提升吞吐量。
- **KV cache (key-value cache)**
  - The attention layer's stored keys and values from prior tokens; reusing it across requests with shared prefixes avoids recomputing the past.
  - 注意力層為先前 token 計算出來並儲存的 key 與 value；當多請求共用前綴時可直接重用，省去重算成本。
- **Full Page Write (FPW)**
  - In Postgres, the first write to a page after a checkpoint writes the entire 8KB page image into the WAL for crash safety — can dominate WAL volume.
  - 在 Postgres 中，checkpoint 後第一次寫某頁時會把整個 8KB 頁面映像寫入 WAL 以確保 crash 安全 — 常常主導 WAL 流量。
- **C2 (command-and-control)**
  - In malware, the channel an infected machine uses to receive instructions and exfiltrate data — moving C2 to a blockchain makes takedown much harder.
  - 在惡意軟體中，受感染主機接收指令與外送資料的通道 — 把 C2 放到區塊鏈會讓下架難度顯著提高。
