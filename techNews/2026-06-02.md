### Stanford CS336's `CLAUDE.md`: Teaching With Claude, Not Outsourcing To It
### Stanford CS336 的 `CLAUDE.md`：把 Claude 當教學助理，不當代寫

[GitHub 連結](https://github.com/stanford-cs336/assignment1-basics/blob/main/CLAUDE.md)

- **Frame**
  - "Language Modeling from Scratch" is intentionally implementation-heavy: Python / PyTorch / Triton with minimal scaffolding. Claude is a teaching aid, not a solution generator.
- **What Claude *may* do**
  - Explain concepts, ask clarifying questions, point at lecture notes / docs, review code, suggest improvements, debug **by guided questioning**, explain error messages, suggest sanity checks and toy examples.
- **What Claude *may not* do**
  - Write Python or pseudocode. Complete TODO sections. Edit student repos. Implement tokenizers, transformers, optimizers, training loops, Triton kernels. Point at third-party implementations. Run bash commands.
- **The pedagogical stance**
  - "Teach the *why*, not the *how*." Prefer tests, invariants, and profiling over direct fixes. When in doubt, refer to course staff.
- **Why it's interesting**
  - First well-known university course shipping a `CLAUDE.md` as part of the syllabus. The shape — what's allowed / what's not — generalises far beyond academia: this is a useful template for "I want the agent to help my junior dev, not write for them."
-------
- **框架**
  - 「Language Modeling from Scratch」這門課刻意實作密集：Python／PyTorch／Triton，幾乎沒鷹架可拿。Claude 在這裡是教學輔助，不是代寫機器。
- **Claude 可以做的事**
  - 解釋概念、提澄清問題、指向講義／文件、看 code 並建議改進、用引導式提問幫忙 debug、解讀錯誤訊息、提出 sanity check 與小型 toy example。
- **Claude 不能做的事**
  - 寫 Python 或 pseudocode。補 TODO 區塊。改學生的 repo。實作 tokenizer、transformer、optimizer、訓練迴圈、Triton kernel。指向第三方實作。執行 bash 指令。
- **教學立場**
  - 「教為什麼，不教怎麼做」。優先用測試、不變式、profiling 來引導，而非直接給修補。拿不準就指向課程助教。
- **為什麼值得看**
  - 第一個知名大學課程把 `CLAUDE.md` 寫進 syllabus。允許／不允許清單的形狀其實能套用得很遠 — 這也是「我希望 agent 是教 junior dev，而不是替他寫」這個場景的好範本。

### `supermemory`: A Memory API That Isn't Just Another RAG
### `supermemory`：不是另一個 RAG 的記憶 API

[GitHub 連結](https://github.com/supermemoryai/supermemory)

- **The distinction**
  - "Memory is **not** RAG. RAG retrieves document chunks — stateless, same results for everyone. Memory extracts and tracks facts **about users** over time."
- **What it does**
  - Memory engine extracts facts, resolves contradictions, **automatically forgets expired info**.
  - User profiles: static facts (long-term) + dynamic context (recent activity).
  - Hybrid search combines RAG (documents) with personalised memory in one query.
  - Connectors sync from Google Drive, Gmail, Notion, OneDrive, GitHub.
  - File processing: PDFs, images (OCR), videos (transcription), code (AST-aware chunking).
- **MCP install**
  - `npx -y install-mcp@latest https://mcp.supermemory.ai/mcp --client claude`. Tools: `memory` (save/forget), `recall` (search), `context` (inject profile).
  - Clients supported: Claude Desktop, Cursor, Windsurf, VS Code, Claude Code, OpenCode, OpenClaw, Hermes.
- **Numbers**
  - **24.2k stars**, 2.2k forks. Claims #1 on LongMemEval, LoCoMo, ConvoMem benchmarks. MIT.
-------
- **核心差異**
  - 「Memory **不是** RAG。RAG 在抓文件片段 — 無狀態、每個人結果相同。Memory 是對**使用者**抽取並追蹤事實、隨時間更新。」
- **能做什麼**
  - 記憶引擎抽取事實、處理矛盾、**自動忘掉過期資訊**。
  - 使用者 profile：靜態事實（長期）+ 動態 context（近期活動）。

  - Connector 串接 Google Drive、Gmail、Notion、OneDrive、GitHub。

  - `npx -y install-mcp@latest https://mcp.supermemory.ai/mcp --client claude`。Tool：`memory`（存／忘）、`recall`（搜尋）、`context`（注入 profile）。
  - 支援 client：Claude Desktop、Cursor、Windsurf、VS Code、Claude Code、OpenCode、OpenClaw、Hermes。

### `fff`: A File-Search Toolkit Built For AI Agents
### `fff`：為 AI agent 設計的檔案搜尋工具

[GitHub 連結](https://github.com/dmtrKovalenko/fff)

- **The performance claim**
  - Stays warm in process — in-memory index + cache. **Sub-10ms** queries vs ripgrep's **3-9 SECONDS** per spawn on large codebases.
- **Why agents care**
  - Typed result objects (path, line, git status) — no text parsing of ripgrep stdout.
  - Cursor pagination across search sessions — agent doesn't blow context fetching too many results.
  - Definition-first classification labels code structure (functions, classes, etc.) — "less wasted context, faster answers".
  - Typo-resistant fuzzy matching with smart-case fallback; frecency + git-awareness.
- **Integrations**
  - Rust crate `fff-search`. C FFI `libfff_c`. Node `@ff-labs/fff-node`. Neovim plugin `fff.nvim`. MCP server for Claude / Cursor / Cline.
- **One-liner MCP install**
  - `curl -L https://dmtrkovalenko.dev/install-fff-mcp.sh | bash`.
- **Stats**
  - **7.3k stars**, MIT. 63.7% Rust, 18.2% Lua, 11.8% TypeScript.
-------
- **效能宣稱**
  - 在 process 內保持暖機 — 記憶體索引 + cache。每次查詢 **<10ms**，對比 ripgrep 在大 codebase 上每次 spawn 要 **3-9 秒**。
- **為什麼 agent 在意**
  - 結果是有型別的物件（path、line、git status） — 不用解析 ripgrep 的 stdout 字串。
  - 跨 session 用 cursor 分頁 — agent 不會因為一次抓太多結果把 context 炸掉。
  - Definition-first 分類：標出程式碼結構（function、class…） — 「context 浪費少，回答更快」。
  - 容忍打錯的模糊比對、smart-case fallback；含 frecency 與 git 狀態感知。
- **整合**
  - Rust crate `fff-search`、C FFI `libfff_c`、Node `@ff-labs/fff-node`、Neovim plugin `fff.nvim`、給 Claude／Cursor／Cline 用的 MCP server。
- **一行 MCP 安裝**
  - `curl -L https://dmtrkovalenko.dev/install-fff-mcp.sh | bash`。
- **數據**
  - **7.3k 星**、MIT。Rust 63.7%、Lua 18.2%、TypeScript 11.8%。

### "I Spent 10× Longer Debugging AI Code Than Writing It"
### 「我花了寫 AI 程式 10 倍的時間在 debug 它」

[原文連結](https://dev.to/harsh2644/i-spent-10x-longer-debugging-ai-code-than-writing-it-15h4)

- **The five-hour incident**
  - 30-second AI prompt → 3 lines handling a list. **No empty-list check.** Two weeks later, a user with zero data crashed prod. The fix: one line. The debug: **5 hours**.
- **The table**
  | Incident | Write | Debug | Ratio |
  |---|---|---|---|
  | Empty-list assumption | 5 min | 5 hours | **60×** |
  | "Works on my machine" | 10 min | 1 day | **144×** |
  | Generic naming (`data`, `result`) | 0 min | 3 hours | **∞** |
- **Why the ratio is real**
  - AI optimises happy paths; edge cases live in the implicit assumptions you didn't articulate.
  - Reverse-engineering unfamiliar code is more expensive than rereading your own.
  - Repeated invisible failures erode trust in your test suite.
- **The four rules**
  - Don't ship code you can't explain line-by-line.
  - Treat AI output as a first draft — rewrite critical sections, edge cases, variable names.
  - Add missing assumptions **explicitly** before merging (empty input, null, malformed).
  - Budget a **debugging tax** — 30 minutes per AI-written function for hardening.
- **Quote**
  - "The fast code isn't free. It's borrowed time."
-------
- **5 小時的事故**
  - 30 秒的 AI 提示 → 3 行處理 list 的程式碼。**沒有空 list 檢查。** 兩週後，一位資料量為 0 的使用者讓 prod 掛掉。修正：一行。Debug：**5 小時**。

  | 情況 | 寫程式 | Debug | 比例 |
  |---|---|---|---|
  | 默默假設 list 非空 | 5 分 | 5 小時 | **60×** |
  | 「我這邊跑得起來」 | 10 分 | 1 天 | **144×** |

- **為什麼比例是真的**
  - AI 把 happy path 最佳化；edge case 全藏在「沒明說出來」的假設裡。
  - 讀別人（AI）寫的程式比讀自己寫的更費神。
  - 反覆出現的隱形錯誤，會慢慢讓你連自己的測試集都不敢信。
- **四條建議**
  - 不要 ship 自己無法逐行解釋的程式。
  - 把 AI 輸出當「初稿」 — 關鍵段落、edge case、變數命名都要自己改過。
  - Merge 前**明確補上**沒寫的假設（空輸入、null、格式錯）。
  - 為每個 AI 寫的函式預留 **30 分鐘 debugging 稅**用來補強。

### In-N-Out Animations for Dialogs: `allow-discrete` + `@starting-style` + `overlay`
### Dialog 的進出動畫：`allow-discrete` + `@starting-style` + `overlay`

[原文連結](https://frontendmasters.com/blog/in-n-out-animations-dialogs-part-1-3/)

- **The problem**
  - Animating in/out of `display: none` used to require JS hacks. Now CSS handles it natively.
- **The three pieces**
  - **`allow-discrete`** lets `display` (and `overlay`) transition — change happens at the *right* moment (immediately when opening, delayed until animation completes when closing).
  - **`@starting-style`** defines the pre-animation state of a newly-rendered element — without it, the "from" state never exists and there's no transition to animate.
  - **`overlay`** keyword: applied to dialog so `::backdrop` participates in the top-layer transition.
- **The three states (reverse source order)**
  - "On the way out" (closed) → "open" → "on the way in" (`@starting-style`).
- **The code**
  - ```css
    dialog {
      transition: 1s opacity, 1s display allow-discrete, 1s overlay allow-discrete;
      &::backdrop { transition: opacity 1s; }
      &:not(:open) { opacity: 0; }
      &:open { opacity: 1; }
      @starting-style { &:open { opacity: 0; } }
    }
    ```
- **Author**: Chris Coyier. Part 1 of 3, published June 1, 2026.
-------
- **問題**
  - 「進出 `display: none`」的動畫過去得靠 JS 黑魔法。現在 CSS 原生就能處理。
- **三個關鍵 piece**
  - **`allow-discrete`**：讓 `display`（與 `overlay`）也能 transition — 變化會在「對的時間點」發生（開啟時立刻、關閉時等動畫完成）。
  - **`@starting-style`**：定義「剛被 render 出來時的狀態」 — 沒它就沒有 from 狀態，動畫無從動起。
  - **`overlay`** 關鍵字：套在 dialog 上，讓 `::backdrop` 也能參與 top-layer 轉場。
- **三個狀態（按 source 反向順序）**
  - 「準備離開」（closed） → 「open」 → 「準備進入」（`@starting-style`）。
- **程式碼**
  - ```css
    dialog {
      transition: 1s opacity, 1s display allow-discrete, 1s overlay allow-discrete;
      &::backdrop { transition: opacity 1s; }
      &:not(:open) { opacity: 0; }
      &:open { opacity: 1; }
      @starting-style { &:open { opacity: 0; } }
    }
    ```
- **作者**：Chris Coyier。三篇系列第 1 篇，發表於 2026-06-01。

### "Streaming an LLM Response, in 4 GIFs"
### 「用 4 個 GIF 看懂 LLM streaming」

[原文連結](https://dev.to/jasmin/streaming-an-llm-response-in-4-gifs-16dh)

- **The four stages**
  - Why streaming exists — 4-second wait vs first token at ~300ms; same total latency, different feel.
  - What's on the wire — Server-Sent Events; text arrives in `delta.text` inside `content_block_delta` events.
  - Reading the stream — iterate chunks, buffer incomplete messages, split on `\n\n`, parse the JSON.
  - **Three common bugs** — ghost streams (forgot `AbortController`), silent truncation (didn't handle `data.type === "error"`), split TCP packets (didn't buffer).
- **The mental model**
  - "Streaming doesn't make the model faster — it makes the wait disappear." Total latency identical, perceived speed ~3× faster.
- **The fix patterns**
  - Use `AbortController` so navigation away cancels the request.
  - Explicit handler for `data.type === "error"` mid-stream.
  - `messages.pop()` to keep the last incomplete fragment for the next chunk.
  - Watch `stop_reason` in `message_delta` to catch `max_tokens` truncation.
- **Author**: Jasmin Virdi. Companion to her earlier "LLM API in 4 GIFs". May 31, 2026.
-------
- **四個段落**
  - 為什麼需要 streaming — 等 4 秒 vs 第一個 token 大概 300ms；總延遲一樣，感覺差很多。
  - 線上長什麼樣 — Server-Sent Events；文字在 `content_block_delta` 事件裡的 `delta.text`。
  - 怎麼讀 stream — 一塊塊讀、把未完成訊息 buffer 起來、用 `\n\n` 切、解析 JSON。
  - **三個常見 bug** — ghost stream（忘了寫 `AbortController`）、靜默截斷（沒處理 `data.type === "error"`）、TCP 封包被切成兩段（沒做 buffer）。
- **心智模型**
  - 「Streaming 不會讓模型更快 — 它只是讓『等待感』消失。」總延遲完全一樣，但感受上快了大約 3 倍。
- **修補模式**
  - 用 `AbortController`，使用者切走頁面就取消請求。
  - 明確處理串流中途的 `data.type === "error"`。
  - 用 `messages.pop()` 把最後一段不完整的留給下一個 chunk。
  - 看 `message_delta` 的 `stop_reason`，偵測 `max_tokens` 造成的截斷。
- **作者**：Jasmin Virdi。她上週「LLM API in 4 GIFs」的姊妹篇。2026-05-31。

## Glossary

- **Hash-anchored edit**
  - An agent-editing scheme where the target of an edit is identified by a content hash (e.g. the SHA of the surrounding lines) rather than by line number — robust to concurrent edits and uses fewer output tokens than line-number diffs.
  - 一種 agent 編輯機制，編輯的目標用「內容雜湊」（例如周邊行的 SHA）標定，不用行號 — 不受並行編輯影響，輸出 token 也比行號 diff 少。
- **Codex CLI / Codex App (OpenAI)**
  - OpenAI's coding-agent surfaces: a terminal CLI and a desktop app — both now route through Amazon Bedrock with the AWS billing model when used via the Bedrock GA endpoint.
  - OpenAI 的編程 agent 介面：終端 CLI 與桌面 app — 透過 Bedrock GA endpoint 使用時，兩者底層都走 Amazon Bedrock、用 AWS 計費。
- **Responses API (Bedrock)**
  - Bedrock's next-generation inference API used to call OpenAI frontier models — supports the streaming / tool-use semantics OpenAI uses, with Bedrock's enterprise-control surface (IAM, PrivateLink, CloudTrail).
  - Bedrock 用來呼叫 OpenAI 前沿模型的新一代推論 API — 支援 OpenAI 那一套 streaming／tool-use 語意，並掛上 Bedrock 的企業控制（IAM、PrivateLink、CloudTrail）。
- **`allow-discrete` (CSS)**
  - A `transition-behavior` value that allows discrete properties (like `display`) to be part of a CSS transition by holding the "old" value until the animation completes (or jumping to the "new" value at the right moment when opening).
  - 一個 `transition-behavior` 值，讓本來是離散變化的屬性（例如 `display`）也能參與 CSS transition — 關閉時保留舊值直到動畫做完，開啟時則在對的時間點直接跳到新值。
- **`@starting-style` (CSS)**
  - The at-rule that defines the **initial** state of a newly-rendered element — required so there's a "from" value for transitions to animate from when the element first appears.
  - 一個 at-rule，用來定義剛被 render 出來的元素的「**初始**」狀態 — 沒它，元素剛冒出來時就沒有 from 值，transition 無從動起。
- **`overlay` keyword (CSS, dialog)**
  - The keyword that makes `<dialog>`'s top-layer state participate in transitions — so the `::backdrop` and dialog can both animate when entering and leaving the top layer.
  - 一個關鍵字，讓 `<dialog>` 的「top layer 狀態」可以加入 transition — 進入或離開 top layer 時，`::backdrop` 與 dialog 都能一起動。
- **Definition-first classification (file-search)**
  - A search-result enhancement that labels each match by the code construct around it (function, class, type, etc.) — so an agent reading results knows the structure of what it found without an extra pass.
  - 搜尋結果的一種加工：每個命中項都附上「它在什麼程式結構裡」（function、class、type…） — agent 讀結果時不用再額外掃一遍就知道是什麼東西。
- **Frecency**
  - A sorting signal combining **frequency** (how often used) and **recency** (how recently used) — used by file searchers to surface the files an agent is most likely to want next.
  - 一種排序訊號：**frequency**（用得多頻繁）加 **recency**（多近用過） — 檔案搜尋拿來把 agent 接下來最可能要的檔案優先排出來。
- **Subagent (typed-schema)**
  - A worker process spawned by an agent that returns its result as a structured object validated by a schema — avoids prose-parsing of natural-language returns and makes parallel merges deterministic.
  - 由 agent 派生的 worker process，回傳結果是經過 schema 驗證的結構化物件 — 不必解析自然語言文字，平行合流時也好處理。
- **AlphaEvolve**
  - DeepMind's Gemini-powered coding agent for *algorithm discovery* — closes the loop between code generation and a numerical fitness signal so it can iteratively improve an algorithm rather than just write one.
  - DeepMind 用 Gemini 驅動的「演算法發現」coding agent — 把程式碼生成與數值化的 fitness 訊號接成迴圈，能反覆優化一個演算法，不只是寫出一份。
