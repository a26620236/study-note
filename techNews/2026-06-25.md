### The 80/20 Rule of AI Code: The Last 20% Takes 80% of the Time
### AI 程式碼的 80/20 法則：最後 20% 吃掉 80% 的時間

[原文連結](https://dev.to/harsh2644/the-8020-rule-of-ai-code-why-the-last-20-takes-80-of-your-time-3pcg)

- **Core**
  - AI nails the happy path (first 80%) fast, but the last 20% — empty/null cases, error handling, domain edge cases, performance cliffs, maintainability — eats most of the time. "30 seconds to generate, 3 hours to finish."
  - The work wasn't eliminated, it was relocated: from writing code to validating it, which still needs real domain knowledge.
- **Advice**
  - Budget ~4x the generation time for shipping; name failure modes and unhappy paths explicitly in the prompt; write failing tests first as concrete targets; consider spec-driven development to make edge cases predictable upfront.
-------
- **核心**
  - AI 能快速搞定 happy path（前 80%），但最後 20% —— 空值／null、錯誤處理、領域邊界案例、效能懸崖、可維護性 —— 才吃掉大部分時間。「30 秒生成，3 小時收尾。」
  - 工作沒有被消滅，而是被搬移了：從「寫程式」搬到「驗證程式」，而後者仍需真正的領域知識。
- **建議**
  - 把出貨時間抓在生成時間的約 4 倍；在 prompt 裡明確點名失敗模式與非順境路徑；先寫會失敗的測試當作具體目標；考慮 spec-driven development，把邊界案例在前期就變得可預測。

### CSS Gap Decorations: Draw Lines in Gaps with the `rule` Property
### CSS Gap Decorations：用 `rule` 屬性在間隙裡畫線

[原文連結](https://master.dev/blog/lets-play-with-gap-decorations/)

- **Core**
  - Gap Decorations let you decorate the gaps in flexbox, grid, and multi-column layouts directly, instead of faking borders with pseudo-elements.
  - The `rule` property mirrors `border` syntax: `.grid { gap: 20px; rule: 4px solid darkred; }` draws a line through every gap.
- **Details**
  - Sub-properties: `rule-width` / `rule-style` / `rule-color`, `rule-inset` (line length within the gap), and `rule-break` (`none` to cross intersections, `intersection` to break at them); values can repeat, e.g. `rule-width: 1px, 1px, 3px;`.
  - Support is Chrome/Edge only at publication — progressive enhancement for now.
-------
- **核心**
  - Gap Decorations 讓你直接裝飾 flexbox、grid、多欄版面的間隙，不必再用 pseudo-element 假造邊框。
  - `rule` 屬性語法仿照 `border`：`.grid { gap: 20px; rule: 4px solid darkred; }` 就會在每道間隙畫線。
- **細節**
  - 子屬性：`rule-width` / `rule-style` / `rule-color`、`rule-inset`（線在間隙中的長度）、`rule-break`（`none` 穿過交叉點、`intersection` 在交叉點斷開）；值可重複，例如 `rule-width: 1px, 1px, 3px;`。
  - 發文時僅 Chrome／Edge 支援 —— 目前先當漸進增強使用。

### Your Database's Isolation Levels Don't Mean What You Think
### 你資料庫的 Isolation Level 跟你想的不一樣

[原文連結](https://master.dev/blog/your-databases-isolation-levels-dont-mean-what-you-think/)

- **Core**
  - SQL-92 defined isolation by which anomalies are forbidden, not by positive guarantees — so the same name (e.g. "Repeatable Read") means different things per vendor, and write skew isn't even in the standard.
  - Write-skew example: two on-call doctors each check that someone else is still on-call, both clock out, zero remain — no forbidden anomaly occurred, but the invariant broke.
- **Vendor reality**
  - Postgres defaults to Read Committed; MySQL/InnoDB to Repeatable Read — fundamentally different. Postgres Repeatable Read = Snapshot Isolation (allows write skew); Serializable = SSI (aborts with `40001`, needs app retry). Oracle "Serializable" is actually Snapshot Isolation.
- **Advice**
  - Pick by behavior you need, not by name; use `SELECT ... FOR UPDATE` for portable row locking; add retry loops for serialization failures; and test with interleaved multi-connection transactions, since single-connection tests hide every anomaly.
-------
- **核心**
  - SQL-92 是用「禁止哪些異常」而非「正向保證」來定義隔離等級 —— 所以同一個名稱（如「Repeatable Read」）在不同廠商意義不同，而 write skew 根本不在標準裡。
  - write skew 範例：兩位值班醫師各自確認「還有別人值班」後都下班，結果零人值班 —— 沒有違反任何被禁止的異常，但不變量被打破了。
- **各廠商現實**
  - Postgres 預設 Read Committed；MySQL/InnoDB 預設 Repeatable Read —— 本質上不同。Postgres 的 Repeatable Read = Snapshot Isolation（允許 write skew）；Serializable = SSI（會以 `40001` 中止，需應用層重試）。Oracle 的「Serializable」其實是 Snapshot Isolation。
- **建議**
  - 依你需要的「行為」而非「名稱」來選；用 `SELECT ... FOR UPDATE` 取得跨廠商可移植的列鎖；為序列化失敗加上重試迴圈；並用多連線交錯的交易來測試，因為單連線測試會把所有異常都藏起來。

### A Practical Guide to SSH Tunnels (-L / -R / -D)
### SSH Tunnel 實用指南（-L / -R / -D）

[原文連結](https://labs.iximiuz.com/tutorials/ssh-tunnels)

- **Local forwarding (-L)**
  - Reach a remote service from your laptop: `ssh -L 8080:localhost:80 host` makes the remote port 80 available at your `localhost:8080` — great for private DBs and internal web apps.
- **Remote forwarding (-R)**
  - Expose a local service through a remote gateway: `ssh -R 8080:localhost:80 gateway` publishes your local port 80 on the gateway — needs `GatewayPorts yes` to bind beyond loopback.
- **Dynamic (-D)**
  - `ssh -D 1080 host` turns the client into a SOCKS proxy so one tunnel reaches an entire private network (vs `-L` needing one tunnel per destination).
  - Mnemonic: -L = client opens the port (Local), -R = server opens the port (Remote); the left side of `local:remote` always opens the new port.
-------
- **本地轉發（-L）**
  - 從你的筆電連到遠端服務：`ssh -L 8080:localhost:80 host` 會把遠端的 80 埠映射到你的 `localhost:8080` —— 很適合連私有 DB 與內部 web app。
- **遠端轉發（-R）**
  - 透過遠端 gateway 對外暴露本地服務：`ssh -R 8080:localhost:80 gateway` 把你本地的 80 埠發佈到 gateway 上 —— 要綁定到 loopback 以外需設定 `GatewayPorts yes`。
- **動態（-D）**
  - `ssh -D 1080 host` 把 client 變成 SOCKS proxy，一條 tunnel 就能連到整個私有網路（相較之下 `-L` 每個目的地都要一條 tunnel）。
  - 記法：-L = client 開埠（Local）、-R = server 開埠（Remote）；`local:remote` 左邊那個永遠是新開的埠。

### apple/container: Run Linux Containers as Lightweight VMs on Apple Silicon
### apple/container：在 Apple Silicon 上把 Linux 容器當輕量 VM 跑

[原文連結](https://github.com/apple/container)

- **Core**

  - Per-container VMs give stronger isolation than kernel-sharing containers, at slightly higher overhead; built in Swift on Apple's Containerization package and macOS 26 virtualization/networking features.

-------
- **核心**
  - Apple 的開源工具把每個 Linux 容器當成 macOS 上獨立的輕量 VM 來跑，使用並產出標準 OCI 映像（可對一般 registry pull/push）。

- **細節**
  - 每容器一個 VM，比共用 kernel 的容器隔離更強，代價是額外負擔略高；以 Swift 寫成，建構在 Apple 的 Containerization 套件與 macOS 26 的虛擬化／網路功能上。

## Glossary

- **MCP (Model Context Protocol)**
  - An open protocol that standardizes how LLM agents call external tools and data sources.
  - 標準化 LLM agent 如何呼叫外部工具與資料來源的開放協議。
- **MDX**
  - Markdown extended with JSX components, so prose can embed structured, schema-checked blocks like `<DataModel>`.
  - 在 Markdown 裡內嵌 JSX 元件的格式，讓文字中可放入像 `<DataModel>` 這種結構化、可檢查 schema 的區塊。
- **Computer Use**
  - An agent capability where the model controls a real UI (browser/desktop) by reading the screen and issuing clicks/keystrokes.
  - 一種 agent 能力：模型透過讀取畫面並發出點擊／按鍵，操作真實的 UI（瀏覽器／桌面）。
- **Tool Calling**
  - Letting an LLM invoke developer-defined functions/APIs, with the model choosing which to call and with what arguments.
  - 讓 LLM 呼叫開發者定義的函式／API，由模型決定要叫哪個、帶什麼參數。
- **Structured Output**
  - Forcing a model's response to conform to a JSON schema so it can be parsed reliably instead of free text.
  - 強制模型的回應符合 JSON schema，讓輸出能被可靠解析，而非自由文字。
- **Write Skew**
  - A concurrency anomaly where two transactions read overlapping data, each pass a check, write different rows, and together break an invariant.
  - 一種並行異常：兩個交易讀到重疊資料、各自通過檢查、寫入不同的列，合起來卻打破了不變量。
- **Snapshot Isolation (SI)**
  - Each transaction reads a consistent snapshot taken at its start; prevents many anomalies but still permits write skew.
  - 每個交易讀取它開始時拍下的一致快照；可防多數異常，但仍允許 write skew。
- **SOCKS Proxy**
  - A generic proxy protocol where the client names a destination per connection, letting one tunnel reach many hosts.
  - 一種通用 proxy 協定，client 為每條連線指定目的地，讓單一 tunnel 能連到許多主機。
- **OCI Image**
  - The Open Container Initiative's standard image format, so containers built by one tool run on any compliant runtime/registry.
  - Open Container Initiative 的標準映像格式，讓某工具建的容器能在任何相容的 runtime／registry 執行。
- **Temporal API**
  - A modern JavaScript date/time API with explicit, timezone-aware types, designed to replace the error-prone `Date`.
  - 一套現代 JavaScript 日期時間 API，型別明確且具時區概念，用來取代容易出錯的 `Date`。
- **Explicit Resource Management (`using`)**
  - A JS declaration that auto-disposes a resource (file, connection) when it leaves scope, like a cleaner try-finally.
  - 一種 JS 宣告，當資源（檔案、連線）離開作用域時自動釋放，像更乾淨的 try-finally。
