### Postmortem on Claude Code Quality Issues (Mar–Apr 2026)
### Claude Code 三到四月品質問題事後檢討

[原文連結](https://www.anthropic.com/engineering/april-23-postmortem)

- **Core**
  - Three independent changes degraded Claude Code over six weeks, creating inconsistent symptoms across users.
  - March 4: reasoning effort default switched from `high` to `medium` for latency — but users wanted intelligence over speed (reverted April 7).
  - March 26: a prompt-cache optimization accidentally cleared thinking history every turn instead of once, making Claude "forgetful and repetitive" (fixed April 10).
  - April 16: a system instruction telling Claude to keep inter-tool text ≤25 words cut coding quality by ~3% (reverted April 20).
- **Going forward**
  - Broader per-model evals for all prompt changes, longer soak periods, gradual rollouts, and internal staff required to use the public build (not internal dev versions).
- **What users get**
  - Usage limits were reset for all subscribers on April 23.
-------
- **核心**
  - 三個獨立改動在六週內疊加導致 Claude Code 退化，症狀在不同使用者身上呈現不一致，難以察覺。
  - 3/4：reasoning effort 預設從 `high` 改成 `medium` 是為了延遲考量 — 但使用者其實偏好智能勝於速度（4/7 回滾）。
  - 3/26：一個 prompt cache 優化的 bug 把每一輪都清空 thinking history（應該只清一次），導致 Claude「健忘又重複」（4/10 修復）。
  - 4/16：一個系統指令要求 Claude 在 tool call 之間文字保持 ≤25 字，意外讓 coding 品質下降約 3%（4/20 回滾）。
- **接下來改變**
  - 所有 prompt 更動會做更廣的 per-model eval、更長的 soak period、漸進 rollout，內部員工也必須用公開版本（不能用內部 dev 版）。
- **使用者得到什麼**
  - 4/23 重置了所有訂閱者的 usage limit 當作補償。

### Code Mode: Collapse 2,500 MCP Endpoints into 2 Tools
### Code Mode：把 2,500 個 MCP endpoint 收成 2 個工具

[原文連結](https://dev.to/zenstack/how-to-save-bloated-mcp-with-code-mode-33e3)

- **Core**
  - Instead of registering every API endpoint as a separate MCP tool, Code Mode exposes a small fixed set (search / execute / schema) and lets the model write code against a schema.
  - Cloudflare reduced 2,500 endpoints to 2 tools and dropped context usage from 2M+ tokens to ~1,000.
- **Why it matters**
  - Traditional MCP bloats the context window because every Zod/JSON schema for every tool gets serialized in the prompt — fast path to running out of tokens before the model has even thought.
  - Code Mode shifts the burden: the model sees the schema once, then writes parameterized queries.
- **Tradeoff**
  - Choosing between MCP and Agent Skills now depends on tool count and schema size — large APIs lean toward Code Mode / Skills.
-------
- **核心**
  - Code Mode 不再把每個 API endpoint 註冊成獨立 MCP tool，而是只暴露一組固定工具（search / execute / schema），讓模型對著 schema 寫程式碼。
  - Cloudflare 把 2,500 個 endpoint 壓成 2 個工具，context 使用量從 200 萬 token 降到約 1,000。
- **為什麼重要**
  - 傳統 MCP 會吃爆 context — 每個 tool 的 Zod / JSON schema 都會被序列化進 prompt，模型還沒開始想就先用光 token。
  - Code Mode 把負擔移轉：模型只看一次 schema，之後就用參數化查詢。
- **取捨**
  - 在 MCP 跟 Agent Skills 之間怎麼選，現在要看工具數量與 schema 大小 — 大型 API 比較適合 Code Mode / Skills。

### 4 Tiny Mistakes That Secretly Destroy App Performance
### 4 個悄悄拖垮 app 效能的小錯誤

[原文連結](https://dev.to/sylwia-lask/4-tiny-mistakes-that-secretly-destroy-app-performance-3cgo)

- **Core**
  - Four common perf foot-guns in JS / React / Angular: inline objects/arrays in JSX props causing re-renders, missing memoization keys, large list rendering without virtualization, and synchronous heavy work in render.
  - Quick fixes: `useMemo` / `useCallback` with right deps, `react-window` / `@tanstack/virtual`, defer heavy work to `requestIdleCallback` or web worker.
- **Why it matters**
  - These are not new but get re-introduced every time AI agents generate components without perf review.
-------
- **核心**
  - JS / React / Angular 四個常見效能地雷：JSX props 寫 inline object/array 觸發 re-render、memoization key 漏掉、大 list render 沒做虛擬化、render 裡做同步重活。
  - 快速修法：`useMemo` / `useCallback` 配正確的 deps、`react-window` / `@tanstack/virtual`、把重活搬到 `requestIdleCallback` 或 web worker。
- **為什麼重要**
  - 這些不是新東西，但每次 AI agent 沒做效能 review 就直接生 component，這些坑就會被重新引入。

## Glossary

- **MCP (Model Context Protocol)**
  - An open protocol standardizing how LLM agents call external tools and data sources.
  - 標準化 LLM agent 如何呼叫外部工具與資料來源的開放協議。
- **Code Mode (for MCP)**
  - A pattern where the LLM writes code against a single schema instead of selecting from many tool descriptions — collapses huge APIs into 2–3 tools.
  - 一種模式：LLM 對著一份 schema 寫程式碼，而不是從一堆 tool 描述裡挑 — 把巨型 API 壓成 2–3 個工具。
- **Agent Skills**
  - Reusable, sandboxed capability bundles that AI coding agents (Claude Code, Cursor, etc.) can install and invoke.
  - 可重用、沙箱化的能力包，AI coding agent（Claude Code、Cursor 等）可以安裝並呼叫。
- **Agent-Native**
  - Software designed so AI agents — not just humans — can operate it natively (stable URLs, machine-readable APIs, idempotent actions).
  - 設計成讓 AI agent（不只是人類）能原生操作的軟體（穩定 URL、機器可讀 API、idempotent 操作）。
- **Soak Period**
  - A monitoring window after a deploy where new code runs in production but on limited traffic, to catch regressions before full rollout.
  - 部署後的觀察期，新版程式只跑部分流量，用來在全量上線前抓 regression。
- **BYOK (Bring Your Own Key)**
  - An AI tool feature letting you plug in your own API key for the underlying model (OpenAI, Anthropic, etc.) instead of being locked to the vendor's billing.
  - AI 工具的功能，讓你帶自己的 API key 接底層模型（OpenAI、Anthropic 等），不被 vendor 的計費綁死。
- **Mutation Testing**
  - A testing technique that mutates source code (flips operators, removes lines) and checks whether your tests catch the change — measures real test strength.
  - 一種測試手法：故意改動原始碼（翻轉運算子、刪除一行），檢查你的 test 是否抓得到 — 衡量 test 的真實強度。
- **Idempotent**
  - An operation safe to retry: running it once or 10 times produces the same end state. Critical for agent reliability.
  - 可安全重試的操作：跑一次或十次最終結果都一樣。對 agent 可靠性很關鍵。
