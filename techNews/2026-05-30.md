### `SQLite is All You Need for Durable Workflows`
### 「SQLite 就夠做 durable workflow」

[原文連結](https://obeli.sk/blog/sqlite-is-all-you-need-for-durable-workflows/)

- **Direct response to DBOS**
  - Agrees with the DBOS framing — durability needs preserved state, not a separate orchestrator — but pushes further: SQLite is enough for the AI-agent workflow class.
- **Architecture**
  - Multiple Obelisk workers writing to **local SQLite** files.
  - **Litestream** replicates SQLite changes asynchronously to S3-compatible storage.
  - An observer pulls databases for inspection / debugging.
- **Why it works for agents**
  - Compute is cheap and disposable; state is the durable thing. Co-locating state with the worker eliminates a network hop per checkpoint.
  - SQL stays as the observability layer, same as the Postgres case.
- **Trade-offs**
  - Limited cross-worker coordination compared to Postgres; suitable when each workflow lives in one worker for its lifetime.
- **Date**: May 29, 2026.
-------
- **直接回應 DBOS**
  - 同意 DBOS 的論點 — durability 真正需要的是「保存狀態」，不是獨立 orchestrator — 但更進一步：對 AI agent workflow 這類場景，SQLite 就夠。
- **架構**
  - 多個 Obelisk worker 寫**本地 SQLite** 檔。
  - **Litestream** 把 SQLite 變更非同步複寫到 S3 相容儲存。
  - 一個 observer 把資料庫拉下來做檢視／除錯。
- **為什麼對 agent 有效**
  - 算力廉價可丟，真正要 durable 的是狀態。狀態跟 worker 同地，省下每個 checkpoint 的網路往返。
  - SQL 依然當 observability 層，跟 Postgres 那套同樣有效。
- **取捨**
  - 跨 worker 協調能力比 Postgres 弱；適合「一個 workflow 一輩子只在同一個 worker 上」的場景。
- **日期**：2026 年 5 月 29 日。

### Builder.io: The AI Product Ladder
### Builder.io：AI 產品三階梯

[原文連結](https://www.builder.io/blog/the-ai-product-ladder)

- **Rung 1 — Single LLM Call**
  - "Summarize" buttons, "Generate description" fields. Fast to ship, looks impressive in demos, dies on edge cases.
- **Rung 2 — Chat with Tools**
  - Claude, ChatGPT, Cursor. Conversational, surfaces reasoning, can call tools. But the chat is **adjacent** to the product, not woven in.
- **Rung 3 — Agent-Native**
  - Every UI button has a matching agent-callable tool with identical underlying logic. The AI feature becomes "indistinguishable from the product itself."
- **Why most apps die at Rung 1**
  - It's "fast to ship and easy to kill". Teams hit "close but wrong" outputs, try to prompt-tweak instead of re-architecting, watch usage drop, deprecate.
- **The recommendation**
  - Plan for Rung 3 from day one. Climbing requires upfront design (shared action model human ↔ agent), not retrofitting.
- **Author**: Matt Abrams, May 27, 2026.
-------
- **第一階 — 單次 LLM 呼叫**
  - 「Summarize」按鈕、「Generate description」欄位。出貨快、demo 漂亮、但碰到 edge case 就死。
- **第二階 — Chat 配工具**
  - Claude、ChatGPT、Cursor。對話式介面、會把推理展示出來、能呼叫 tool。但 chat 是「**附在**產品旁邊」，不是「**織進**產品裡」。

  - 每個 UI 按鈕都對應一個 agent 可呼叫的 tool，底層邏輯共用。「AI 功能與產品本身難以區分」。

- **建議**
  - 第一天就為第三階設計。要爬上去，需要前期規劃（人類與 agent 共用 action model），不是事後改造能補的。

### CSS `@function`: Reusable Property Behaviour With 10 Gotchas
### CSS `@function`：可重用屬性行為，但有 10 個地雷

[原文連結](https://frontendmasters.com/blog/the-fundamentals-and-dev-experience-of-css-function/)

- **What it does**
  - Lets you define a named function that returns a CSS value — no more duplicating long `calc()` expressions or polluting the global custom property namespace.
- **Syntax**
  - ```css
    @function --hello-world() {
      result: "Hello World";
    }

    @function --the-answer(--required, --arg2: 0px) returns <number> {
      result: calc(var(--required) * 10);
    }
    ```
- **10 DX gotchas (selected)**
  - Wrong argument count → **silent failure**.
  - Variables inside the function can't be type-registered globally.
  - **No recursion** — a function can't call itself.
  - Can't feed the result of one call into the same function elsewhere.
  - Comma-separated variables don't spread naturally into parameters.
  - Result type mismatches **silently return `initial`** rather than warning.
- **Status**
  - Author Jane Ori writes "soon, but not yet" — DX is rough but the potential is real.
-------
- **能做什麼**
  - 讓你定義一個有名字、會回 CSS 值的 function — 不必再到處複製貼上長串 `calc()`，也不必把所有東西塞到全域 custom property。
- **語法**
  - ```css
    @function --hello-world() {
      result: "Hello World";
    }

    @function --the-answer(--required, --arg2: 0px) returns <number> {
      result: calc(var(--required) * 10);
    }
    ```
- **10 個 DX 地雷（節錄）**
  - 參數個數不對 → **靜默失敗**。
  - function 內變數沒辦法全域註冊型別。
  - **不支援遞迴** — function 不能自己呼叫自己。
  - 沒辦法把一次呼叫的結果再餵回同一個 function。
  - 逗號分隔的變數不會自動展開成多個參數。
  - 結果型別不合會**靜默回 `initial`**，不會警告。
- **狀態**
  - 作者 Jane Ori 用「快了，但還沒」形容 — DX 還粗糙，但潛力是真的。

### `contrast-color()` Is Baseline Across All Engines *(weekly: Smashing)*
### `contrast-color()` 已成各引擎 Baseline *(週末來源：Smashing)*

[原文連結](https://www.smashingmagazine.com/2026/05/building-self-correcting-color-systems-contrast-color/)

- **What it does**
  - Takes a colour, returns black or white — whichever wins on contrast. The browser runs the WCAG math during style computation, before paint, no JS hydration delay.
- **Why it matters**
  - **~70%** of websites still fail WCAG contrast. Moving the check into native CSS is the first scalable fix.
- **Examples**
  - ```css
    .button {
      background-color: var(--brand-color);
      color: contrast-color(var(--brand-color));
    }
    ```
  - Softened text via `color-mix`:
    ```css
    color: color-mix(in oklch, contrast-color(var(--bg)) 80%, var(--bg));
    ```
  - Progressive enhancement: wrap in `@supports (color: contrast-color(red)) { ... }`.
- **Browser support**
  - Chrome 147 (April 2026), Firefox 146, Safari 26.0 — **Baseline Newly Available, April 2026**. All three pass the Web Platform Tests.
- **Author**: Durgesh Pawar, May 28, 2026.
-------
- **能做什麼**
  - 給它一個顏色，回傳黑或白 — 取對比較高的那個。瀏覽器在繪製前的 style computation 就跑完 WCAG 對比運算，沒有 JS hydration 的延遲。
- **為什麼重要**
  - 約 **70%** 的網站在 WCAG 對比這項仍不及格。把判斷移進原生 CSS 是第一個能 scale 的補救。
- **範例**
  - ```css
    .button {
      background-color: var(--brand-color);
      color: contrast-color(var(--brand-color));
    }
    ```
  - 用 `color-mix` 軟化文字色：
    ```css
    color: color-mix(in oklch, contrast-color(var(--bg)) 80%, var(--bg));
    ```
  - 漸進增強：包在 `@supports (color: contrast-color(red)) { ... }`。
- **瀏覽器支援**
  - Chrome 147（2026 年 4 月）、Firefox 146、Safari 26.0 — **2026 年 4 月起進 Baseline Newly Available**。三家都通過 Web Platform Tests。
- **作者**：Durgesh Pawar，2026 年 5 月 28 日。

### `sibling-index()` / `sibling-count()`: Stagger Without `:nth-child()` *(weekly: Smashing)*
### `sibling-index()`／`sibling-count()`：不靠 `:nth-child()` 做交錯 *(週末來源：Smashing)*

[原文連結](https://www.smashingmagazine.com/2026/05/mathematical-layouts-sibling-index-sibling-count/)

- **What they do**
  - `sibling-index()` returns the element's position among siblings as a number; `sibling-count()` returns the total. Both usable inside `calc()`.
- **The unlock**
  - Staggered cascade effects (delays, transforms, colours) in **one CSS line**, without `:nth-child()` rule lists or JS index-setting.
- **Example pattern**
  - ```css
    .item {
      animation-delay: calc(sibling-index() * 100ms);
      transform: translateY(calc((sibling-index() - sibling-count() / 2) * 4px));
    }
    ```
  - Two declarations replace what used to need 20+ `:nth-child(n)` rules or runtime `--i` setting via JS.
- **Why care**
  - List rendering libraries (React's `.map()`, framework loops) typically didn't carry index into CSS without adding a custom property per item — that's now free at the CSS layer.
-------
- **能做什麼**
  - `sibling-index()` 回傳元素在兄弟中的位置（數字）；`sibling-count()` 回總數。兩者都能放在 `calc()` 裡。
- **解鎖的能力**
  - 用**一行 CSS** 做交錯效果（delay、transform、顏色），不用列一堆 `:nth-child()` 規則，也不用 JS 設 index。
- **範例**
  - ```css
    .item {
      animation-delay: calc(sibling-index() * 100ms);
      transform: translateY(calc((sibling-index() - sibling-count() / 2) * 4px));
    }
    ```
  - 兩行宣告取代原本要寫 20+ 條 `:nth-child(n)` 或 JS 動態設 `--i` 的做法。
- **為什麼值得記**
  - List 渲染（React 的 `.map()`、各框架的 loop）原本不會把 index 帶進 CSS，要每個 item 加 custom property — 現在 CSS 層直接給你。

### Adaptive Hedged Requests: p99 Latency -74% *(weekly: InfoQ)*
### 自適應 Hedged Request：p99 降 74% *(週末來源：InfoQ)*

[原文連結](https://www.infoq.com/articles/adaptive-hedged-requests-p99-latency/)

- **The mechanism**
  - When a primary request is slow, fire a backup; take whichever finishes first, cancel the other. Proactive, not reactive — unlike retries which wait for failure.
- **The numbers**
  - p99: **65.0ms → 17.3ms** (-74%).
  - In a system with 100 downstream services at 1% straggler each, **63%** of top-level requests hit at least one straggler — hedging is how you catch them.
- **Architecture**
  - **DDSketch** (O(1) streaming quantile sketch, ±1% accuracy) for per-host latency distributions.
  - **30-second tumbling window** (two rotating sketches) to track shifting conditions.
  - **Token bucket budget** caps hedges at e.g. 10% of total traffic — prevents the load-doubling spiral during real outages.
  - Latency measured at first response byte (HTTP) or first-token-arrival (LLM endpoints).
- **vs. classic retries / timeouts**
  - Retries add load to already-failing backends; static timeouts go stale as distributions drift; hedging learns from live traffic and is rate-limited.
- **Reference impl**
  - Open-source Go HTTP `RoundTripper` (`bhope/hedge`) — drop-in, zero initial config.
- **Author**: Prathamesh Bhope, May 28, 2026.
-------
- **機制**
  - 主請求慢的時候，發一個備援請求；誰先回就用誰，另一個取消。是主動而非反應式 — 跟「失敗才 retry」相反。
- **數字**
  - p99：**65.0ms → 17.3ms**（-74%）。
  - 在 100 個下游、每個 1% straggler 的系統中，**63%** 的上層請求會碰到至少一個 straggler — hedging 就是用來救這 63%。
- **架構**
  - **DDSketch**（O(1) 串流式 quantile sketch，誤差 ±1%）做各 host 的延遲分佈。
  - **30 秒滾動視窗**（兩個 sketch 交替）追蹤情勢變化。
  - **Token bucket 預算**把 hedge 流量限制在例如 10% — 避免真正掛掉時雙倍打死後端。
  - HTTP 量「第一個 byte」；LLM endpoint 量「first-token-arrival」。
- **與傳統 retry／timeout 的差別**
  - Retry 會在後端已經出問題時加重負擔；靜態 timeout 隨分佈漂移就過期；hedging 從即時流量學，並有流量上限保護。
- **參考實作**
  - 開源 Go HTTP `RoundTripper`（`bhope/hedge`）— 直接 drop-in，零初始設定。

## Glossary

- **Litestream**
  - A streaming replication daemon for SQLite — pushes the WAL incrementally to S3-compatible storage so a local SQLite file gets cloud-grade durability without an extra database.
  - 給 SQLite 用的串流複寫 daemon — 把 WAL 增量推到 S3 相容儲存，讓本地 SQLite 檔也能得到雲端等級的 durability，不需要再多一個資料庫。
- **DDSketch**
  - A streaming quantile sketch with O(1) updates and bounded relative error (±1%) — used for live p50/p95/p99 estimates on high-traffic services. Memory is logarithmic in the value range.
  - 一種串流式 quantile sketch，更新是 O(1)、相對誤差有界（±1%） — 用於高流量服務的即時 p50／p95／p99 估算。記憶體佔用對值域呈對數。
- **Hedged request**
  - The latency-reduction pattern of firing a backup request when the primary looks slow, then cancelling the loser — proactively races against stragglers rather than waiting for them to fail.
  - 一種降延遲模式：主請求看起來慢時就發一個備援，誰輸誰被取消 — 主動跟 straggler 賽跑，而不是等它徹底失敗。
- **Straggler**
  - In a fan-out request, a backend node that is slower than its peers but doesn't actually fail. At scale, almost every top-level request hits at least one — they dominate p99 even when failure rates are tiny.
  - 在 fan-out 場景中，那個比同儕慢但沒真的壞掉的下游節點。規模一大，幾乎每個上層請求都會碰到一個 — 即使失敗率很低，它們也會主宰 p99。
- **TTFT (Time To First Token)**
  - The latency from request submit to the first streamed token arriving — the meaningful "p99" for LLM endpoints, since the byte-level metric hides streaming behaviour.
  - 從送出請求到第一個串流 token 抵達的延遲 — LLM endpoint 真正有意義的 p99，因為位元組層的指標看不出串流體驗。
- **CSS `@function`**
  - A native CSS feature for defining named functions returning CSS values — like `calc()` but reusable, typed, and parameterised. Avoids polluting the global custom-property namespace.
  - CSS 原生功能，可定義有名字、回 CSS 值的 function — 像 `calc()` 但可重用、有型別、有參數。避免把所有東西塞進全域 custom property。
- **`contrast-color()`**
  - A CSS colour function that returns the black-or-white value with better contrast against a given colour — moves WCAG contrast logic out of JS and into native style computation.
  - 一個 CSS 顏色 function：給它一個顏色，回傳對比較高的黑或白 — 把 WCAG 對比邏輯從 JS 搬到原生 style computation。
- **`sibling-index()` / `sibling-count()`**
  - CSS functions usable inside `calc()` that return an element's index among siblings and the total sibling count — enables stagger effects without `:nth-child()` lists or JS index setting.
  - 可在 `calc()` 中使用的 CSS function，分別回元素在兄弟中的 index 與兄弟總數 — 讓你不用寫 `:nth-child()` 列表、不用 JS 設 index 也能做交錯效果。
- **Agent-Native (Rung 3)**
  - The product architecture where every UI affordance maps to an agent-callable tool with identical underlying logic — humans and agents share one action model, not two.
  - 一種產品架構：每一個 UI 操作都對應到一個 agent 可呼叫的 tool，底層邏輯共用 — 人與 agent 共享同一份 action model，不是兩份。
- **CLI-first agent pattern**
  - The alternative to MCP proposed by Quandri: instead of permanent tool schemas eating context, load a skill at invocation time that explains how to use the existing CLI — much smaller token footprint.
  - Quandri 提出的 MCP 替代方案：不要永久放著 tool schema 一直吃 context，而是在呼叫當下載入一個 skill 解釋怎麼用既有 CLI — token 佔用小得多。
