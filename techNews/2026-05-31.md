### `liteparse`: LlamaIndex's Fast Local PDF / DOCX / XLSX Parser in Rust
### `liteparse`：LlamaIndex 用 Rust 寫的本地端 PDF／DOCX／XLSX 解析器

[GitHub 連結](https://github.com/run-llama/liteparse)

- **What it does**
  - Stand-alone OSS parser focused on "fast and light". Runs entirely locally — no cloud, no LLM service required.
  - Extracts text with bounding boxes, so downstream agents know *where* on the page each line is.
- **Inputs / outputs**
  - Inputs: PDF, DOCX, XLSX, PPTX, plus images (JPG, PNG, GIF…).
  - Outputs: JSON with bounding boxes, plain text with layout preserved, PNG screenshots for agent consumption.
- **Distribution**
  - One project, four install paths: `npm`, `pip`, `cargo`, browser **WASM**. CLI: `lit parse document.pdf` with flags for OCR, page targeting, format.
- **Honest limitations**
  - Dense tables, multi-column layouts, handwritten text — they recommend their commercial LlamaParse instead.
- **Stats**
  - Apache 2.0, **8k+ stars**, +925 today, primary language Rust (70.4%), 50 releases.
-------
- **能做什麼**
  - 一個獨立開源解析器，主打「快又輕」。完全在本地跑 — 不需要雲、不需要 LLM 服務。
  - 抽出文字時帶 bounding box，下游 agent 才知道每段文字在頁面**哪個位置**。
- **輸入／輸出**
  - 輸入：PDF、DOCX、XLSX、PPTX、加各種圖片（JPG、PNG、GIF…）。
  - 輸出：帶 bounding box 的 JSON、保留版面的純文字、給 agent 看的 PNG 截圖。
- **發佈管道**
  - 同一個專案、四種安裝：`npm`、`pip`、`cargo`、瀏覽器 **WASM**。CLI：`lit parse document.pdf`，旗標可控 OCR、指定頁面、輸出格式。
- **誠實列出的限制**
  - 密集表格、多欄版型、手寫文字 — 他們建議改用商業版 LlamaParse。
- **數據**
  - Apache 2.0、**8k+ 星**、今天 +925、主語言 Rust（70.4%）、50 個 release。

### AI Agents Are Great at 80% of Our Code — The Other 20% Is Why We Still Need Seniors
### AI agent 能搞定 80% 的程式碼 — 剩下的 20% 才是資深工程師存在的理由

[原文連結](https://dev.to/mickyarun/ai-agents-are-great-at-80-of-our-code-the-other-20-is-why-we-still-need-seniors-3lh5)

- **The 80%**
  - API scaffolding, boilerplate, Zod validation schemas, service configs, env management refactors. "What used to be a half-day of copy-paste-and-tweak is now a conversation."
- **The 20%**
  - "Payment can't transition from `complete` back to `pending`." Agents build happy paths beautifully and skip illegal-state, idempotency, and duplicate-webhook cases. They optimise for **completion, not correctness**.
- **Senior-only skills**
  - System judgment (which paths matter), institutional memory (which scenarios broke production at 2am), architecture enforcement, negative-case thinking, cross-system invariants.
- **Team recommendations**
  - Make architecture machine-readable — encode it as lints and constraints the agent **can't** ignore.
  - Test negative cases rigorously.
  - Mandatory senior review on critical (payment, auth) paths.
  - Provide shared utilities so agents stop reinventing logic.
- **The punchline**
  - *"Replace your senior with AI? You get speed plus silent disasters. Enable your senior with AI? You get an architect with an army."*
- **Author**: Arun Rajkumar, CTO of Atoa (FCA-authorised UK payments). May 28, 2026.
-------
- **80% 的部分**
  - API 樣板、boilerplate、Zod 驗證 schema、service config、env 管理重構。「以前要花半天複製貼上微調的事，現在是一場對話。」

- **給團隊的建議**
  - 把架構**機器可讀化** — 寫成 agent **沒辦法忽略**的 lint 與 constraint。
  - 嚴格測試 negative case。
  - 關鍵路徑（金流、認證）必經資深工程師審核。
  - 提供共用 utility，讓 agent 不要每次重新發明輪子。
- **金句**

### Practical Interface Patterns for AI Transparency *(weekly: Smashing)*
### AI 透明度的實用介面模式 *(週末來源：Smashing)*

[原文連結](https://www.smashingmagazine.com/2026/05/practical-interface-patterns-ai-transparency/)

- **Why spinners fail**
  - Spinner says "downloading"; agentic AI is "thinking through options + creating content". Users can't tell stalled from problem-solving — that uncertainty becomes anxiety.
- **The five patterns**
  - **Living Breadcrumb** — subtle pulsing status for low-stakes work (drafting an email). Doesn't demand attention.
  - **Dynamic Checklist** — sequential steps with clear progress for high-stakes flows. Manages unpredictable timing.
  - **Thinking Toggle** — progressive disclosure to a sanitised reasoning log, for expert users.
  - **Audit Trail** — persistent post-task record of decisions, for verification.
  - **Partial Success Design** — granular status: what succeeded, what failed — not binary pass/fail.
- **Existing examples**
  - Perplexity AI's real-time activity listing; Devin AI's dynamic checklist.
- **The principle**
  - Match message weight to visibility level; ensure audit trails persist beyond real-time progress.
- **Author**: Victor Yocco, PhD. May 13, 2026.
-------
- **為什麼 spinner 不行**
  - Spinner 表示「正在下載」；agentic AI 是「在思考選項、產生內容」。使用者無法分辨「卡住了」與「正在解問題」 — 這種不確定感最後變成焦慮。
- **五種模式**
  - **Living Breadcrumb** — 在背景做微妙脈動的狀態提示，適合低風險任務（如草擬郵件）。不打擾注意力。
  - **Dynamic Checklist** — 依序顯示步驟、進度清楚，適合高風險工作流。能處理時間預估不準的情況。
  - **Thinking Toggle** — progressive disclosure 切到「淨化過的推理 log」，給專家使用者看。
  - **Audit Trail** — 任務後仍保留決策紀錄，方便事後驗證。
  - **Partial Success Design** — 顆粒度更細的狀態：哪些成功、哪些失敗 — 不要二值的全過／全失敗。
- **既有例子**
  - Perplexity AI 的即時活動列表；Devin AI 的動態 checklist。
- **核心原則**
  - 訊息「分量」對齊「可見度」；audit trail 要在即時進度之外仍能查到。
- **作者**：Victor Yocco（PhD）。2026 年 5 月 13 日。

### Designing Stable Interfaces for Streaming Content *(weekly: Smashing)*
### 為串流內容設計穩定的 UI *(週末來源：Smashing)*

[原文連結](https://www.smashingmagazine.com/2026/05/designing-stable-interfaces-streaming-content/)

- **The three core bugs**
  - Scroll keeps yanking you back to the bottom even when you scrolled up to read.
  - Layout instability: content grows, pushes everything down, breaks reading.
  - DOM-rebuild storms: every chunk recreates elements, cursors flicker, layout recalculates.
- **Scroll-control pattern**
  - Track user intent with a boolean flag. Auto-scroll only when at bottom; once user scrolls up, stop.
  - **60px gap threshold** to prevent jitter. Reset the flag on a new stream.
- **Layout stability**
  - **Write into a live text node** instead of rebuilding DOM. New paragraphs only on line breaks; otherwise extend the existing node.
  - Cursor flicker and layout thrash disappear.
- **Render batching**
  - Buffer characters and flush once per frame with `requestAnimationFrame` — decouples arrival speed from render frequency.
- **Stream interruption**
  - Clear buffers, remove cursors, **mark the response incomplete** in the DOM, reset state — don't just cancel a timer.
- **ARIA / a11y essentials**
  - `role="log"` + `aria-live="polite"` + `aria-atomic="false"` on chat containers.
  - `aria-label` on retry buttons; `aria-hidden="true"` on decorative cursors; honour `prefers-reduced-motion` by rendering instantly.
- **Author**: Joas Pambou, May 1, 2026.
-------
- **三個核心問題**
  - 即使你已經往上捲讀東西，畫面還是被一直拉回最底。
  - 版面不穩：內容一直長、把其他東西往下推、讀起來會斷。
  - DOM rebuild 風暴：每塊新內容都重建元素，cursor 閃、layout 一直重算。
- **捲動控制模式**
  - 用一個布林旗標追使用者意圖。在底部時才自動 scroll；一旦使用者往上捲，停下。
  - **60px 縫隙閾值**避免抖動。新的 stream 開始時把旗標 reset。
- **版面穩定**
  - **直接寫入一個 live text node**，不要每次重建 DOM。只有遇到換行才建新段落，其他就延長現有 node。
  - cursor 閃爍與 layout 抖動會消失。
- **Render 批次**
  - 把字元 buffer 起來，每個 frame 用 `requestAnimationFrame` flush 一次 — 把「資料抵達速度」與「渲染頻率」解耦。
- **Stream 被中斷時**
  - 清掉 buffer、移除 cursor、**在 DOM 上標記回應未完成**、reset 狀態 — 不能只是 cancel 一個 timer 完事。
- **ARIA／a11y 必備**
  - chat 容器加 `role="log"` + `aria-live="polite"` + `aria-atomic="false"`。
  - retry 按鈕加 `aria-label`；裝飾性 cursor 加 `aria-hidden="true"`；尊重 `prefers-reduced-motion`，要瞬間 render 完。

### OpenBSD's `openrsync` Lands as a Single-Process rsync Rewrite
### OpenBSD 釋出 `openrsync`：單一 process 的 rsync 重寫版

[GitHub 連結](https://github.com/kristapsdz/openrsync)

- **What it is**
  - An ISC-licensed implementation of the rsync protocol, originally written for the rpki-client project on OpenBSD.
- **Compatibility**
  - Works with modern rsync (tested against 3.1.3) — anything supporting protocol 27 interoperates. Accepts a subset of rsync's CLI flags.
- **The architectural difference**
  - Traditional rsync forks separate **generator** and **receiver** processes. `openrsync` runs both in a **single event-loop process** — simpler model, less IPC overhead.
- **Portability**
  - Officially OpenBSD; CI tests on Linux, FreeBSD, NetBSD, macOS, OmniOS across x86_64, aarch64, s390x.
- **Status**
  - Funded by NetNod, IIS.SE, SUNET, 6connect. Now part of the OpenBSD base. 701 stars, 36 forks.
-------
- **是什麼**
  - 一份 ISC 授權的 rsync 協定實作，原本是給 OpenBSD 上的 rpki-client 專案用的。
- **相容性**
  - 跟現代 rsync（測試版本 3.1.3）相容 — 任何支援 protocol 27 的版本都能互通。CLI 旗標取 rsync 子集。
- **架構差異**
  - 傳統 rsync 會 fork 出獨立的 **generator** 與 **receiver** process。`openrsync` 把兩者放進**單一事件迴圈 process** — 模型較簡單、IPC 開銷較小。
- **可攜性**
  - 官方支援 OpenBSD；CI 在 Linux、FreeBSD、NetBSD、macOS、OmniOS 上跑，覆蓋 x86_64、aarch64、s390x。
- **狀態**
  - 由 NetNod、IIS.SE、SUNET、6connect 出資。已併入 OpenBSD base。701 星、36 forks。

## Glossary

- **CDC (Change Data Capture)**
  - The pattern of streaming a source database's row-level changes (inserts/updates/deletes) as an ordered event log to downstream consumers — the foundation of modern data-ingestion pipelines.
  - 把來源資料庫的列級變更（insert／update／delete）以「有序事件流」的形式串給下游消費者的模式 — 現代資料攝取 pipeline 的基礎。
- **Higress**
  - An open-source API gateway built on Envoy, positioned as a modern alternative to ingress-nginx for Kubernetes ingress with Wasm plugin support.
  - 一個建在 Envoy 上的開源 API gateway，定位是 Kubernetes ingress 領域中 ingress-nginx 的現代替代品，支援 Wasm plugin。
- **Meta-skill (harness)**
  - A skill whose output is *other* skills and agents — instead of doing a task, it generates the infrastructure that other agents will use. "Skill" of the second order.
  - 一種輸出**其他 skill 與 agent** 的 skill — 它本身不執行任務，而是產生「其他 agent 要用的基礎設施」。算是「第二層」的 skill。
- **Agent architecture patterns (Pipeline / Fan-out / Expert Pool / Producer-Reviewer / Supervisor / Hierarchical)**
  - The six recurring shapes of multi-agent workflows — sequential chain, parallel-then-merge, route-by-context, dual roles for quality, central dispatcher, recursive delegation. The harness repo names these explicitly.
  - 多 agent workflow 的六種反覆出現的形狀 — 循序鏈、平行加合流、依 context 路由、為品質設雙角色、中央派發、遞迴授權。`harness` 這個 repo 把它們明確命名出來。
- **SAST (Static Application Security Testing)**
  - The practice of analysing source code (without executing it) for security vulnerabilities. Traditional SAST tools rely on pattern matching; agentic SAST like Metis uses LLM reasoning instead.
  - 對原始碼做靜態分析（不執行程式）找資安漏洞的做法。傳統 SAST 靠規則比對；像 Metis 這種 agentic SAST 改成讓 LLM 做推理。
- **RAG (Retrieval-Augmented Generation)**
  - An LLM pattern where, before generating, the system retrieves relevant context (docs, code, files) and stuffs it into the prompt — lets the model "know" project-specific information without retraining.
  - 一種 LLM 模式：生成前先檢索相關 context（文件、程式碼、檔案）塞進 prompt — 讓模型「知道」專案特定資訊，不用重新訓練。
- **LangGraph**
  - An agent-orchestration library where workflows are graphs of nodes (agents / tools / decisions) with explicit edges — Grab's multi-agent support system runs on this.
  - 一個 agent 編排函式庫：workflow 是一張由節點（agent／tool／判斷）與明確邊組成的圖 — Grab 的多 agent 支援系統建在這上面。
- **Living Breadcrumb / Dynamic Checklist / Thinking Toggle**
  - Three of Smashing's five transparency UI patterns for agentic AI — respectively a subtle background status, an explicit progress list, and a hide/show reasoning panel.
  - Smashing 提出的「agentic AI 透明度」五個 UI 模式中的三個 — 分別是「背景式低調狀態」、「明確進度列表」、「可展開／收起的推理 panel」。
- **Live text node (streaming UI)**
  - The technique of mutating a single existing DOM text node as new chunks arrive instead of creating new elements — eliminates layout thrash and cursor flicker during LLM streaming.
  - 串流 UI 的一種技巧：新內容到時直接「改動同一個已存在的 DOM text node」，而不是建新元素 — LLM 串流時不會有 layout 抖動或 cursor 閃爍。
- **`aria-live="polite"`**
  - The ARIA attribute that tells screen readers to announce updates *when convenient*, not immediately — the right setting for a continuously-updating chat / log so users aren't interrupted mid-sentence.
  - 一個 ARIA 屬性，告訴螢幕閱讀器「在方便時」播報更新，而不是「立刻」 — 對不斷更新的 chat／log 是正確選擇，使用者讀句子讀到一半才不會被打斷。
