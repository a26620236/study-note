### Cloudflare 攜手 Stripe：Agent 可自助開雲端帳號、買網域、部署程式

  - Lowers integration friction for end-to-end automation, but raises the bar for spend governance and policy controls.
- **Watch**
  - Whether the same protocol is adopted by other cloud providers — if yes, it becomes a de-facto standard for agent provisioning.
-------
- **核心**
  - 新協議由 Cloudflare 與 Stripe Projects 共同設計，把流程拆成 Discovery、Authorization、Payment 三段。
  - Agent 呼叫指令列出可用服務，接著拿到安全核發的憑證與付款 token，全程不用人去貼 API key。
  - 人類仍需在迴圈中授權與同意服務條款，但不再有其他手動步驟。
- **影響**
  - 這是第一條真正的「runtime 花錢通道」— agent 可以像真人客戶一樣訂閱、按用量計費。

### Anthropic Postmortem on April Claude Code Quality Issues
### Anthropic 公開四月 Claude Code 品質事件 postmortem

[原文連結](https://www.anthropic.com/engineering/april-23-postmortem)

- **Three root causes**
  - **Mar 4** — Default reasoning effort silently switched from `high` to `medium` to cut latency; reverted Apr 7 after users preferred intelligence.
  - **Mar 26** — A cache-clearing optimization fired every turn instead of only on idle sessions, making Claude appear forgetful and repetitive; fixed Apr 10.
  - **Apr 16** — A "≤25 words between tool calls" verbosity prompt unexpectedly degraded coding quality across models; reverted Apr 20.
- **Corrective actions**
  - Broader evals before any system prompt change, mandatory soak periods, and more staff dogfooding public builds.
  - Usage limits were reset for all subscribers on Apr 23 as compensation.
- **Why this matters**
  - Reinforces that small, "safe-looking" prompt or harness tweaks can silently change model behavior at scale — applies to your own production agents too.
-------
- **三個根因**
  - **3/4** — 預設 reasoning effort 從 `high` 偷偷改成 `medium` 想降低延遲；4/7 因使用者偏好智慧度而還原。
  - **3/26** — 一個原本只想在 idle session 清舊推理的快取優化，誤觸發成每一輪都清，導致 Claude 顯得健忘又重複；4/10 修好。
  - **4/16** — 「工具呼叫之間文字 ≤25 字」的精簡 prompt 意外讓多個模型編程品質下降；4/20 還原。
- **改正措施**
  - 任何 system prompt 變更前要做更廣的評估、強制 soak 期、更多員工試用 public build。
  - 4/23 為所有訂閱者重置用量上限作為補償。
- **重點是**
  - 一個看似安全的小 prompt 或 harness 調整，在大規模下可能悄悄改變模型行為 — 同樣適用於你自己的 production agent。

### Tilde.run: Transactional Agent Sandbox with Versioned Filesystem
### Tilde.run：交易式 agent 沙盒與版本化檔案系統

[Show HN 連結](https://tilde.run)

- **Core idea**
  - Every agent run is wrapped as an atomic transaction: changes either commit together or roll back entirely.
  - Unifies GitHub repos, S3 buckets, Google Drive into a single `~/sandbox` filesystem with full version history.
  - Built on technology from lakeFS (the team's earlier data-versioning platform).
- **Three guarantees**
  - **Reversibility** — roll back any agent run with one command.
  - **Isolation** — fresh container per run, network calls audited.
  - **Control** — granular policies and approval gates.
- **Use case**
  - Useful when an agent operates on real data and you cannot afford partial-failure side effects (half-written files, mixed-up commits).
-------
- **核心概念**
  - 每次 agent 執行被包成原子交易：所有變更一起 commit，否則整個 rollback。
  - 把 GitHub repo、S3 bucket、Google Drive 統一成一個 `~/sandbox` 檔案系統，保留完整版本歷史。
  - 底層用團隊先前 lakeFS（資料版本化平台）的技術。
- **三項保證**
  - **可逆**：一個指令回滾任何 agent 執行。
  - **隔離**：每次執行用全新 container、網路請求被稽核。
  - **控管**：細緻的政策與核准關卡。
- **適用情境**
  - 當 agent 操作真實資料、又不能忍受半失敗副作用（寫一半的檔案、亂掉的 commit）時很有用。

### Simon Willison: "Vibe Coding and Agentic Engineering Are Getting Closer Than I'd Like"
### Simon Willison：「Vibe coding 與 agentic engineering 已經近到讓我不安」

[原文連結](https://simonwillison.net/2026/May/6/vibe-coding-and-agentic-engineering/)

- **Argument**
  - "Vibe coding" (intuition-driven, prompt-and-pray) and "agentic engineering" (rigorous, spec-driven, verified) were initially distinct disciplines.
  - In practice the boundary is blurring — agents being given freer rein, and rigorous practitioners increasingly prompting on intuition.
- **Why care**
  - The two approaches have different acceptance criteria. Mixing them silently means review and ops teams can't tell which standard a piece of code was actually built to.
-------
- **論點**
  - 「Vibe coding」（憑直覺、寫完看運氣）與「agentic engineering」（嚴謹、spec-driven、需驗證）原本是兩個不同學派。
  - 實務上邊界正在模糊 — agent 被放手做更多事，嚴謹的工程師也越來越憑直覺下 prompt。
- **為什麼要在意**
  - 兩種做法接受標準不一樣。混在一起又不講清楚，review 與 ops 團隊就分不出某段程式碼是用哪一套標準寫的。

  - 社群型產品要在多個介面 fan-out 使用者資料時，第三方 auth-as-a-service 容易變成熱路徑瓶頸。

### Malware Disguised as a "Pre-Interview Code Review" — A LinkedIn Recruiter Scam
### 假冒「面試前 code review」夾帶惡意程式 — LinkedIn 招募詐騙案例

[原文連結](https://dev.to/vladimirnovick/a-linkedin-recruiter-sent-me-malware-disguised-as-a-pre-interview-code-review-2k3j)

- **What happened**
  - A "recruiter" sent a take-home repo with malicious npm scripts disguised as build/test tooling.
  - `npm install` itself triggered the payload — the developer never even ran the project.
- **Defenses**
  - Audit `package.json` `scripts` (especially `preinstall`, `postinstall`) before running `npm install`.
  - Run candidate / unknown repos inside a disposable VM or container, never on the host machine.
  - Treat unsolicited "interview tasks" with the same suspicion as any unverified attachment.
-------
- **發生什麼**
  - 自稱「招募」的人寄了 take-home repo，裡面 npm scripts 被改造成惡意程式，偽裝成 build／test 工具。
  - 跑 `npm install` 本身就觸發 payload — 開發者根本沒執行專案就中招。
- **防禦**
  - 跑 `npm install` 前先審 `package.json` 的 `scripts`（特別是 `preinstall`、`postinstall`）。
  - 把候選人 / 不明 repo 放在拋棄式 VM 或 container 跑，不要在主機上跑。
  - 來路不明的「面試任務」要當成不明附件一樣警戒。

## Glossary

- **Agent skill**
  - A reusable, process-driven instruction pack that an AI coding agent loads to follow a specific workflow (e.g. spec-driven development, security review).
  - 一個 AI 編程 agent 可載入的可重用指令包，內含特定工作流程的處理步驟（例如 spec-driven 開發、資安審查）。
- **Vibe coding**
  - Building software by prompting an AI on intuition, accepting its output, and iterating without rigorous specs or verification.
  - 憑直覺對 AI 下 prompt、接受其輸出並反覆調整，過程中不寫嚴格規格、也不做驗證的軟體開發方式。
- **Agentic engineering**
  - The opposite end: spec-driven, agent-executed development with explicit verification gates and review.
  - 與 vibe coding 相對：spec-driven、由 agent 執行、設明確驗證關卡與審查的開發方式。
- **Reasoning effort**
  - A model parameter (low / medium / high) that controls how much extended thinking the model does before answering — higher effort = better quality but slower.
  - 控制模型在回答前做多少延伸思考的參數（low／medium／high）— 越高品質越好但越慢。
- **Soak period**
  - A delay between merging a change and rolling it out broadly, used to surface regressions before they hit all users.
  - 變更合併後到全面上線之間的緩衝期，用來在波及所有使用者之前先發現回歸問題。
- **Transactional filesystem**
  - A filesystem where a batch of changes commits atomically — either all changes apply, or none do — enabling clean rollback.
  - 一次性批次變更要嘛全部成功、要嘛全部回滾的檔案系統，支援乾淨的回退。
- **Stripe Projects**
  - Stripe's product layer that lets agents act as buyers — provisioning subscriptions, paying providers, and being billed on usage on behalf of a user.
  - Stripe 推出的產品層，讓 agent 能代表使用者扮演買方 — 訂閱服務、付錢給供應商、按用量被計費。
- **TUI (Terminal User Interface)**
  - A keyboard-driven interface that runs inside a terminal, common for fast, low-overhead developer tools.
  - 在終端機內跑、以鍵盤操作為主的介面，常用於追求快速與低開銷的開發者工具。
- **Better Auth**
  - An open-source TypeScript auth library that runs in your own backend, positioned as an alternative to managed auth-as-a-service.
  - 一個跑在自己後端的開源 TypeScript 驗證函式庫，定位為 managed auth-as-a-service 的替代方案。
