### `rtk`: CLI Proxy That Cuts Agent Token Usage 60–90%
### `rtk`：壓縮工具輸出、給 agent 省 60–90% token 的 CLI Proxy

[GitHub 連結](https://github.com/rtk-ai/rtk)

- **What it does**
  - Sits between your shell commands (`git`, `cargo`, test runners, file ops) and the agent — filters and compresses output before it lands in context.
- **Four techniques**
  - Smart filtering (drop comments / whitespace / boilerplate), grouping (files by directory, errors by type), truncation, deduplication (repeated log lines collapsed with counts).
- **Measured impact**
  - A 30-minute Claude Code session: ~118,000 tokens without rtk → ~23,900 tokens with it (80% reduction).
- **Integration**
  - 13 platforms: Claude Code, Copilot, Cursor, Gemini CLI, Windsurf, Cline, others. Many use pre-tool hooks to auto-rewrite commands so adoption is "100% per conversation" with zero developer effort.
- **Stack**
  - Single Rust binary, zero external dependencies.
-------
- **它做什麼**
  - 夾在 shell 指令（`git`、`cargo`、test runner、檔案操作）與 agent 之間 — 把輸出在進入 context 前先過濾與壓縮。
- **四個技巧**
  - 智能過濾（去註解／空白／樣板）、群組化（依資料夾合併檔案、依型別合併錯誤）、截斷、去重（重複 log 收成「出現 N 次」）。
- **實測效果**
  - 30 分鐘 Claude Code session：未用 rtk ~118,000 token → 用 rtk ~23,900 token（省 80%）。
- **整合**
  - 13 個平台：Claude Code、Copilot、Cursor、Gemini CLI、Windsurf、Cline 等。多數透過 pre-tool hook 自動改寫指令，做到「每次對話都 100% 採用」、開發者零成本。
- **技術棧**
  - 單一 Rust binary，零外部依賴。

### 12-Factor Agents: A Production Checklist for LLM Apps
### 12-Factor Agents：LLM 應用的 production 檢查清單

[GitHub 連結](https://github.com/humanlayer/12-factor-agents)

- **The 12 factors (selected)**
  - **Own your prompts** (prompts are code, not framework magic), **own your context window**, **own your control flow** (don't let LLM decide all the routing).
  - **Tools as structured outputs**, **unify execution & business state**, **launch/pause/resume APIs**.
  - **Contact humans with tools** (escalation uses the same tool-call mechanism), **compact errors into context**, **small focused agents**, **trigger from anywhere**, **stateless reducer pattern**.
- **Core insight**
  - "The fastest way to get good AI software in front of customers is to take small, modular concepts from agent building and incorporate them into existing products" — i.e. retrofit, don't rebuild.
- **Audience**
  - Engineers building customer-facing AI features who need to clear the 70–80% prototype quality bar and reach production reliability.
-------
- **12 條（節錄）**
  - **自有 prompt**（prompt 就是程式碼，不要靠框架自動代填）、**自有 context window**、**自有 control flow**（不要把所有路由決策交給 LLM）。
  - **工具作為結構化輸出**、**統一執行與業務狀態**、**launch/pause/resume API**。
  - **用 tool 機制聯絡人類**（升級告警走同一套 tool call）、**錯誤要壓進 context**、**小而聚焦的 agent**、**從任何地方觸發**、**stateless reducer 模式**。
- **核心觀點**
  - 「把 AI 軟體最快送到客戶面前的做法，是把 agent 建構中的小而模組化的概念融進既有產品」 — 改造，不要從頭重建。
- **適合誰**
  - 在做客戶面 AI 功能、要從原型 70–80% 品質躍進到 production 等級可靠度的工程師。

### Forge: Guardrails Lift a Local 8B Model to 86.5% on Agentic Evals
### Forge：用 guardrail 把本地 8B 模型在 agentic eval 拉到 86.5%

[GitHub 連結](https://github.com/antoinezambelli/forge)

- **Numbers**
  - Ministral-3 8B on llama-server: 86.5% across a 26-scenario eval suite; 76% on the hardest tier.
- **Guardrails (the trick)**
  - **Rescue parsing** — fix malformed tool calls automatically.
  - **Retry nudges** — guide the model back when validation fails.
  - **Step enforcement** — ensure required workflow steps run.
  - **Context management** — VRAM-aware budgets with tiered compaction.
- **Three integration shapes**
  - `WorkflowRunner` (full lifecycle), Guardrails middleware (drop into your own orchestration), or as an OpenAI-compatible proxy (`python -m forge.proxy`).
- **Backends**
  - Ollama, llama-server, Llamafile, Anthropic — same Python API.
- **Why this matters**
  - Pattern: small open model + structured guardrails can outperform a much larger model used "naively" — especially relevant for cost / privacy-sensitive workloads.
-------
- **數字**
  - Ministral-3 8B 跑在 llama-server：26 題 eval 的整體達 86.5%；最難一級 76%。
- **核心技巧：guardrail**
  - **Rescue parsing**：自動修補格式不對的 tool call。
  - **Retry nudges**：在驗證失敗時把模型導回正軌。
  - **Step enforcement**：強制必要步驟一定要跑。
  - **Context management**：感知 VRAM 預算、分層壓縮 context。
- **三種整合方式**
  - `WorkflowRunner`（完整生命週期）、guardrail middleware（接到自己的編排）、OpenAI 相容 proxy（`python -m forge.proxy`）。
- **支援後端**
  - Ollama、llama-server、Llamafile、Anthropic — 同一套 Python API。
- **為什麼重要**
  - 模式：小型開源模型 + 結構化 guardrail 可以勝過「直接呼叫」的大模型 — 對成本／隱私敏感場景特別實用。

### React Server Components Land in TanStack Start
### React Server Components 進入 TanStack Start

[原文連結](https://frontendmasters.com/blog/react-server-components-in-tanstack/)

- **API shape**
  - `createServerFn()` to wrap server-only components; `renderServerComponent()` to ship pre-rendered markup minus the rendering code.
  - Explicit `CompositeComponent` helpers replace Next.js's file-based "use server" conventions.
- **Mechanics**
  - RSCs can `await` databases or APIs directly — server-side execution only.
  - Interactive content passes through as props → it auto-becomes a client component.
  - Suspense boundaries stream async data while other parts render.
- **Measured impact**
  - Sample app: 308KB → 203KB production bundle (the `lucide-react` icon tree got eliminated from the client trip).
- **Honest limitation**
  - By the time your server function runs, the component has *already rendered*. So RSCs can't accept dynamic client-side props that influence rendering — only references and children.
-------
- **API 形狀**
  - 用 `createServerFn()` 包僅在伺服器執行的元件；`renderServerComponent()` 把預先 render 過的 markup 送到 client，且不夾帶 render 程式碼。
  - 用明確的 `CompositeComponent` helper 取代 Next.js 那種「use server」的檔案約定。
- **機制**
  - RSC 可以直接 `await` 資料庫或 API — 因為只在伺服器執行。
  - 互動內容以 props 傳入 → 會自動成為 client component。
  - Suspense boundary 串流非同步資料，其他部分照常 render。
- **實測效果**
  - 範例 app：production bundle 從 308KB 降到 203KB（`lucide-react` icon 樹從 client 旅程被消掉）。
- **誠實的限制**
  - 你的 server function 要跑時，元件「已經被 render 過」。所以 RSC 不能吃會影響 render 的動態 client props，只能接受 reference 與 children。

  - 一個 CISA 承包商的「Private-CISA」repo（命名雖叫 private、實際公開），內含：
    - 3 個 AWS GovCloud 帳戶的管理員憑證。

    - 內部 artifactory 憑證（對供應鏈後門特別有價值）。

## Glossary

- **Pre-training (in LLM context)**
  - The initial, expensive training phase that gives a model its base knowledge from internet-scale text — distinct from "post-training" (RLHF / fine-tuning) that shapes behaviour.
  - 模型訓練的第一個、成本最高的階段，靠 internet 規模的文本給模型基礎知識 — 與後續的 RLHF／微調等「post-training」分開。
- **Antigravity (Google)**
  - Google's agent-first developer platform — sits above Gemini API and provides workflow orchestration, subagent coordination, and an associated CLI.
  - Google 的 agent-first 開發者平台 — 蓋在 Gemini API 之上，提供工作流編排、subagent 協調、與配套 CLI。
- **Claude plugin**
  - A packaged extension for Claude Code containing some combination of MCP servers, slash-commands, sub-agents, and skills — installed via Claude Code's `/plugin` command.
  - 給 Claude Code 用的擴充套件，可包含 MCP server、slash command、sub-agent、skill 的組合 — 透過 Claude Code 的 `/plugin` 指令安裝。
- **Pre-tool hook**
  - A Claude Code (or similar agent harness) hook that runs *before* a tool call executes — can inspect or rewrite the call. `rtk` uses this to wrap shell commands.
  - Claude Code（或類似 agent harness）中在「工具呼叫執行前」觸發的 hook — 可檢查或改寫該呼叫。`rtk` 用它包覆 shell 指令。
- **Rescue parsing**
  - A pattern where the harness automatically repairs malformed tool-call JSON from the model instead of failing — common reliability fix for smaller open models.
  - Harness 自動修補模型輸出的格式錯誤 tool-call JSON 的做法，不直接失敗 — 對小型開源模型常見的可靠度修補。
- **`createServerFn()` (TanStack)**
  - TanStack Start primitive that marks a function as server-only — the body executes on the server and the result streams to the client.
  - TanStack Start 的原語，把一個函式標記為「僅在伺服器執行」 — 函式 body 跑在伺服器，結果串流給 client。
- **GovCloud (AWS)**
  - AWS's isolated region for US government workloads — separate accounts, strict ITAR / FedRAMP compliance, no shared infrastructure with commercial AWS.
  - AWS 給美國政府工作負載的隔離區 — 獨立帳號、嚴格的 ITAR／FedRAMP 合規、不與商用 AWS 共用基礎設施。
- **Artifactory**
  - JFrog's binary / package repository, commonly used as an organisation's internal source of truth for built artifacts — leaked creds enable supply-chain compromise.
  - JFrog 的二進位／套件儲存庫，常作為組織內部「已建構產物」的權威來源 — 憑證一外洩就可能被用來做供應鏈攻擊。
- **Stateless reducer (agent pattern)**
  - Designing an agent as a pure function `(state, event) → newState` — easier to test, restart, and scale than long-lived stateful loops.
  - 把 agent 設計成純函式 `(state, event) → newState` — 比長壽有狀態迴圈更容易測試、重啟、擴容。
