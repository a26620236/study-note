### `codegraph`: Pre-Indexed Code Knowledge Graph Cuts Agent Tokens 59%
### `codegraph`：預先索引整個 codebase，agent token 降 59%

[GitHub 連結](https://github.com/colbymchenry/codegraph)

- **Core**
  - Parses your repo with tree-sitter, extracts nodes (functions, classes) and edges (calls, imports, inheritance), stores them in a local SQLite database with full-text search.
  - File watchers using native OS events keep the index in sync — no manual rebuilding.
- **Integration**
  - MCP server. Auto-detects Claude Code, Cursor, Codex CLI, opencode and registers itself.
- **Numbers (7 real repos tested)**
  - ~35% cost reduction, ~59% fewer tokens, ~70% fewer tool calls vs the same agent without `codegraph`.
  - Larger repos win more — up to 81% token savings on Tokio.
- **Why it works**
  - Agents stop re-scanning files for "where is `foo()` defined". They query the graph once, get a precise answer, and move on.
-------
- **核心**
  - 用 tree-sitter 解析 repo，抽出 node（函式、類別）與 edge（呼叫、import、繼承），存進本地 SQLite 並提供全文搜尋。
  - 用作業系統原生事件做 file watcher，索引自動同步 — 不必手動重建。
- **整合方式**
  - MCP server。自動偵測 Claude Code、Cursor、Codex CLI、opencode 並登錄自己。
- **數字（用 7 個真實 repo 測試）**
  - 費用降 ~35%、token 降 ~59%、tool call 降 ~70%（與沒有 `codegraph` 的同一 agent 相比）。
  - Repo 越大效果越好 — 在 Tokio 上 token 省到 81%。
- **為什麼有效**
  - Agent 不必每次都掃整個專案找「`foo()` 定義在哪」。直接查圖、拿到精確答案、繼續做事。

### `andrej-karpathy-skills`: 4 Karpathy-Style Skills in One `CLAUDE.md`
### `andrej-karpathy-skills`：把 Karpathy 的 4 條經驗濃縮成一份 `CLAUDE.md`

[GitHub 連結](https://github.com/multica-ai/andrej-karpathy-skills)

- **The four skills**
  - **Think Before Coding** — state assumptions, surface multiple interpretations, ask before guessing.
  - **Simplicity First** — write the minimal code that solves the asked problem; avoid speculative features.
  - **Surgical Changes** — only edit what's necessary; no drive-by refactor of unrelated code.
  - **Goal-Driven Execution** — define verifiable success criteria; loop until met.
- **What pitfalls these fix**
  - Silent assumptions (pick an interpretation without surfacing tradeoffs).
  - Overcomplication (bloated abstractions when "do X" would suffice).
  - Incidental changes (touching code orthogonal to the request).
- **Why it's small but useful**
  - One file, no install ceremony. You can paste-in or drop into `.claude/`. Great minimal complement to bigger skill packs.
-------
- **四條 skill**
  - **想清楚再寫**：列出假設、提出多種解讀、不確定就問清楚。
  - **保持簡單**：只寫解決被問問題的最小程式碼，避免投機式新功能。
  - **外科式修改**：只動必要的部分，不順手重構不相關的程式碼。
  - **目標導向**：先定義可驗證的成功條件，反覆迭代直到達成。
- **修了什麼陷阱**
  - 沉默假設（自選一種解讀但不把 tradeoff 攤開）。
  - 過度複雜化（明明「做 X」就好卻搬出一堆抽象）。
  - 順手改動（改了與請求不相干的程式碼）。
- **為什麼小但有用**
  - 一份檔案，無安裝儀式。可以直接貼進對話或丟到 `.claude/`。對大型 skill pack 是很好的最小補丁。

### tokenspeed: A Live Visualisation of What "N tokens/s" Actually Feels Like
### tokenspeed：把「N tokens／秒」實際感覺視覺化的小工具

[原文連結](https://mikeveerman.github.io/tokenspeed/)

- **What it does**
  - Streams text, code, reasoning, or simulated agent interactions at user-controlled speeds (5–800 tok/s).
- **The insight**
  - Identical tok/s rates *feel dramatically different* depending on content type — code is more token-dense than prose, so "30 tok/s" of code feels faster than 30 tok/s of English.
  - "Unless you've actually watched tokens stream at those rates, the numbers are hard to internalize."
- **Useful for**
  - Calibrating user expectations when comparing model benchmarks; planning the streaming UX of an agentic product so it doesn't feel slow even at realistic tok/s.
-------
- **它做什麼**
  - 用 5–800 tok/s 的可調速度，串流文字、程式碼、推理、模擬 agent 互動。
- **核心洞察**
  - 相同 tok/s 速度下，內容類型不同感受差距極大 — 程式碼 token 密度比一般文字高，「30 tok/s」的程式碼會感覺比「30 tok/s」的英文還快。
  - 「除非親眼看過那個速度下的串流，數字根本沒辦法內化。」
- **適合用於**
  - 在比較模型 benchmark 時校準使用者預期；設計 agent 產品的串流 UX，讓真實 tok/s 下也不會讓人覺得卡。

### Testing Safari on a Budget — Five Cost-Saving Paths Without an iPhone or Mac
### 沒有 iPhone／Mac 也能測 Safari 的五條省錢路徑

[原文連結](https://frontendmasters.com/blog/testing-safari-on-a-budget/)

- **Why bother**
  - Safari holds ~17% browser share and powers all iOS / iPadOS browsers; you can't ignore it.
- **The options**
  - **WebKit forks** (e.g. GNOME Web) — close but not identical (no Apple Pay, slightly different rendering).
  - **Web testing platforms** (BrowserStack / Browserling / TestingBot) — easy but laggy for interaction-heavy testing.
  - **Remote Macs** (AWS / MacinCloud / Scaleway) — full Safari, no local hardware.
  - **CI/CD** (Playwright + GitHub Actions on WebKit) — great for regression, no interactive debugging.
  - **Refurbished or end-of-cycle Macs** — comprehensive, with business-expense / student-discount / cosmetic-damage tricks; check battery health > 80%.
- **Take-home**
  - Hybrid is usually right: refurb Mac for development, CI WebKit for regression, BrowserStack only when an iOS version-specific bug shows up.
-------
- **為什麼要測**
  - Safari 約佔瀏覽器市佔 17%，且所有 iOS／iPadOS 瀏覽器底層都是 Safari — 無法忽略。
- **可選路徑**
  - **WebKit fork**（如 GNOME Web） — 很接近但非完全一致（沒 Apple Pay、render 細節有差）。
  - **線上測試平台**（BrowserStack／Browserling／TestingBot） — 上手快，但互動密集測試會卡。
  - **遠端 Mac**（AWS／MacinCloud／Scaleway） — 完整 Safari，不必買硬體。
  - **CI/CD**（Playwright + GitHub Actions 跑 WebKit） — 適合 regression，沒互動 debug。
  - **整新／世代末 Mac** — 最完整。可走報帳、學生折扣、外觀瑕疵機；先看電池健康度 > 80%。
- **重點**
  - 通常混搭最划算：整新 Mac 做開發、CI WebKit 做 regression、只在出 iOS 版本特定 bug 時開 BrowserStack。

### Upcoming CSS `border-shape`: Reshape an Element Without Losing Its Border
### 即將到來的 CSS `border-shape`：重塑元件、但保住 border 與 box-shadow

[原文連結](https://frontendmasters.com/blog/border-shape/)

- **The problem with `clip-path`**
  - It clips everything — including the border and box-shadow. So "speech bubble with a stroke" needs ugly workarounds.
- **What `border-shape` does**
  - Reshapes the element while keeping `border` and `box-shadow` rendering against the new outline.
  - Composes with the existing `shape()` function for arbitrary outlines.
- **Known limits at this stage**
  - Text doesn't auto-reflow into the new shape — anything outside is ignored; cut-in shapes just clip the text against the original rect.
  - To get text to reflow, combine with `shape-outside` and split the element into halves.
- **Status**
  - Listed as "upcoming"; not yet broadly shipped in browsers. Worth tracking if your design system uses `clip-path` for chip/badge/callout shapes.
-------
- **`clip-path` 的問題**
  - 它把所有東西都剪掉 — 包括 border 與 box-shadow。所以「帶描邊的對話框」要用很醜的 workaround。
- **`border-shape` 做什麼**
  - 重塑元件，但 `border` 與 `box-shadow` 會沿著新的輪廓繪製。
  - 可與既有的 `shape()` 函式組合做任意輪廓。
- **目前限制**
  - 文字不會自動流入新形狀 — 輪廓外的字會被忽略，凹陷形狀只是把字裁掉、版面仍以原矩形計算。
  - 想讓文字回流，要配合 `shape-outside` 並把元件拆成左右兩半。
- **狀態**
  - 文章標示「即將到來」；瀏覽器尚未廣泛支援。若你的 design system 用 `clip-path` 做 chip／badge／callout 形狀，值得追蹤。

### Firefox 148 Disables `asm.js` Optimisations by Default
### Firefox 148 預設關閉 `asm.js` 最佳化

[原文連結](https://spidermonkey.dev/blog/2026/05/20/saying-goodbye-to-asmjs.html)

- **What changes**
  - Effective Firefox 148 (May 20, 2026), `asm.js` is no longer specially optimised; it just runs as regular JavaScript via the JIT.
  - Full removal planned for a future release.
- **Why**
  - WebAssembly took over; SpiderMonkey now ships BaldrMonkey (optimising) and RabaldrMonkey (baseline) — significantly more advanced than the `asm.js` pipeline ever was.
  - Maintaining both was an attack-surface and maintenance cost without benefit.
- **Impact**
  - Minimal — existing `asm.js` code still works, just slower. Migrating to WebAssembly gets you faster execution and smaller binaries.
- **Trivia**
  - `asm.js` once enabled the famous Epic Citadel-in-4-days port to the web. It paved the road for WebAssembly's existence.
-------
- **變動**
  - Firefox 148（2026/5/20）起，`asm.js` 不再走專用最佳化路徑，改走一般 JS 的 JIT。
  - 完全移除排在未來的版本。
- **為什麼**
  - WebAssembly 已經接棒；SpiderMonkey 目前的 BaldrMonkey（最佳化）與 RabaldrMonkey（baseline）比 `asm.js` 那條 pipeline 強得多。
  - 同時維護兩條路徑只是徒增攻擊面與維護成本。
- **影響**
  - 影響很小 — 既有 `asm.js` 仍可跑、只是變慢。改走 WebAssembly 可同時拿到更快與更小的 binary。
- **小註**
  - `asm.js` 當年讓 Epic Citadel 在 4 天內被 port 到網頁，是 WebAssembly 出現之前的關鍵跳板。

### Railway 8-Hour Outage: GCP Auto-Suspended Their Production Account
### Railway 8 小時停擺：GCP 自動化把他們的 production 帳號停權

[原文連結](https://blog.railway.com/p/incident-report-may-19-2026-gcp-account-outage)

- **What happened**
  - May 19, 22:10 UTC: monitoring detected API failures. By 22:19 the team had traced it to a Google Cloud automated platform-wide suspension of Railway's production account.
  - GCP restored access at 22:29 — but the cascade had already begun.
- **Why it cascaded**
  - Railway's edge proxies (even ones on AWS and Railway Metal) depended on a GCP-hosted control-plane API for routing. When cached routes expired, regions *not* under GCP went down too.
  - Result: 8-hour incident, peak impact was *all* customer workloads unreachable, with persistent disks not restored until 23:54.
- **The fix Railway commits to**
  - Distribute the control plane across multiple cloud providers — eliminate the single-cloud dependency.
- **Lesson**
  - Watch where your "globally available" services secretly depend on a single cloud's API. Multi-region isn't multi-cloud.
-------
- **發生什麼**
  - 5/19 22:10 UTC：監控偵測到 API 失敗。22:19 確認根因是 Google Cloud 把 Railway production 帳號做了平台級自動停權。
  - 22:29 GCP 恢復存取 — 但連鎖反應已經開始。
- **為什麼會連鎖**
  - Railway 的 edge proxy（包括跑在 AWS 與 Railway Metal 上的）路由仰賴一個跑在 GCP 上的 control-plane API。一旦路由快取過期，連 *沒在 GCP 上的* 區域也跟著掛。
  - 結果：8 小時的事件，峰值是「所有客戶工作負載都不可達」，持久磁碟到 23:54 才恢復。
- **Railway 的修法承諾**
  - 把 control plane 分散到多家雲端供應商 — 消除單雲依賴。
- **教訓**
  - 注意你「全球可用」的服務是不是偷偷依賴某家雲的單一 API。多區域不等於多雲。

## Glossary

- **Supply-chain attack (extension flavour)**
  - Compromising a developer's editor extension marketplace to push malicious code that runs with the developer's local privileges — increasingly the easiest path into a target organisation.
  - 攻擊者污染開發者所用的編輯器擴充套件市場、推送在開發者本地權限下執行的惡意程式 — 是目前最容易進入目標組織的攻擊路徑之一。
- **MCP server**
  - A server that exposes tools, resources, or prompts to LLM agents over the Model Context Protocol — agents can talk to it the same way regardless of editor.
  - 透過 Model Context Protocol 把工具、資源、prompt 暴露給 LLM agent 的伺服器 — 不論用什麼編輯器，agent 都用相同方式與它對話。
- **LSP (Language Server Protocol)**
  - The standard protocol IDEs use to talk to language servers for autocomplete, go-to-definition, find-references. Embedding LSP in an agent gives it the same code intel an IDE has.
  - IDE 用來和語言伺服器溝通的標準協議，提供自動補全、跳轉定義、找引用等功能。把 LSP 嵌進 agent，等於給 agent 一份 IDE 級的程式碼智慧。
- **DAP (Debug Adapter Protocol)**
  - The standard protocol IDEs use to talk to debuggers (breakpoints, step in/out, watch variables) — pair with LSP and an agent can debug, not just edit.
  - IDE 用來和 debugger 溝通的標準協議（斷點、step in／out、watch 變數） — 與 LSP 搭配後，agent 不只能改、還能 debug。
- **SynthID**
  - Google's invisible watermarking technique for AI-generated text / image / audio / video that survives common edits — used to flag generated content programmatically.
  - Google 的隱形浮水印技術，套用在 AI 生成的文字／圖像／音訊／影片上，能承受常見的編輯動作 — 用於可程式化地辨識生成內容。
- **`asm.js`**
  - A 2013-era strict subset of JavaScript that compilers like Emscripten target for near-native speed — superseded by WebAssembly, now being retired in Firefox.
  - 2013 年代的嚴格 JS 子集，Emscripten 等編譯器拿它做為輸出目標以接近原生速度 — 已被 WebAssembly 取代，Firefox 現正退役它。
- **`shape()` and `border-shape` (CSS)**
  - `shape()` declares an arbitrary path; `border-shape` (upcoming) uses such a path to reshape an element while preserving its `border` and `box-shadow` — `clip-path`'s successor.
  - `shape()` 用來宣告任意路徑；`border-shape`（即將推出）用這種路徑重塑元件，同時保留 `border` 與 `box-shadow` — 是 `clip-path` 的繼任者。
- **Control plane**
  - The component of a distributed system that holds configuration and routing decisions — separate from the data plane that handles actual traffic. Concentrating it in one cloud is a single point of failure.
  - 分散式系統中持有設定與路由決策的部件，與處理實際流量的 data plane 分開。把它集中在單一雲就是單點故障。
- **Hash-anchored edit**
  - An edit operation that includes a hash of the file's expected current content; the edit is rejected if the file has changed underneath — prevents agents from overwriting fresh changes.
  - 一種編輯操作，會帶上「預期當前檔案內容」的 hash；若檔案在過程中被改過就拒絕該編輯 — 避免 agent 蓋掉新變更。
