### Agent Skills as Anti-Rationalization Runbooks
### Agent Skills：用反偷懶 runbook 取代提示文件

[原文連結](https://addyosmani.com/blog/agent-skills/)

- **Core**
  - Agent skills are markdown workflows — not reference docs — with explicit steps, checkpoints, and exit criteria.
  - Each skill ships with an "anti-rationalization table" pairing common shortcut excuses with pre-written rebuttals.
  - Addy installs them via `/plugin marketplace add addyosmani/agent-skills`, exposing slash commands like `/spec`, `/plan`, `/build`, `/test`, `/review`, `/ship`.
- **Why it matters**
  - Agents naturally take the shortest path to "done" and skip invisible work (specs, tests, review) — skills encode the senior-engineer scaffolding that prevents this.
  - A complex feature might activate ~11 skills, while a bug fix activates 3 — scope scales to the work, not the prompt.
- **Five non-negotiables**
  - Surface assumptions, resolve conflicting requirements, push back when wrong, choose boring solutions, and touch only what's requested.
-------
- **核心**
  - Agent skill 是 markdown 寫成的工作流（不是參考文件），有明確步驟、檢查點與結束條件。
  - 每個 skill 內建「反偷懶對照表」：把 agent 可能用來跳過步驟的藉口，事先準備好反駁話術。
  - 安裝方式 `/plugin marketplace add addyosmani/agent-skills`，會掛上 `/spec`、`/plan`、`/build`、`/test`、`/review`、`/ship` 等 slash 指令。
- **為什麼重要**
  - Agent 天生會走最短路徑去「完成」任務，跳過 spec、測試、review 這些隱性工作；skill 把資深工程師的流程骨架明文化，逼 agent 走完整套。
  - 複雜功能可能會觸發 11 個 skill，bug fix 只啟用 3 個；範圍跟著工作大小走，不是跟著 prompt。
- **五條鐵律**
  - 把假設講出來、把矛盾的需求釐清、該反駁就反駁、選無聊但穩定的解、只動被要求的部分。

### TanStack Form Released for React
### TanStack Form 推出 React 強型別表單庫

[原文連結](https://frontendmasters.com/blog/introducing-tanstack-form/)

- **Pitch**
  - Strongly typed, headless, performance-focused form library — TanStack's answer to React Hook Form / Formik.
  - Infers the entire form data shape from `defaultValues` so field names and values are type-checked end-to-end.
- **API surface**
  - `useForm({ defaultValues, onSubmit })` returns a `form` object.
  - Field-level validators on `onSubmit` / `onChange` / `onBlur`; array fields with `pushValue` / `removeValue`.
  - Reactivity via `useStore` and `<Subscribe>`; composition with `fieldContext` and `formComponents`.
- **Why now**
  - Forms remain the most painful part of React; the strong-typing-by-inference angle is the differentiator vs RHF.
-------
- **賣點**
  - 強型別、headless、注重效能的表單庫，是 TanStack 對 React Hook Form / Formik 的回應。
  - 從 `defaultValues` 反推整個表單資料結構，欄位名稱和值都能端到端被型別檢查。
- **API 樣貌**
  - `useForm({ defaultValues, onSubmit })` 拿到 `form` 物件。
  - 欄位層級的驗證可掛在 `onSubmit` / `onChange` / `onBlur`；陣列欄位用 `pushValue` / `removeValue`。
  - 響應式靠 `useStore` 與 `<Subscribe>`；組合性靠 `fieldContext` 與 `formComponents`。
- **為什麼現在出**
  - 表單仍是 React 最痛的一塊，「靠 inference 自動推型別」是它跟 React Hook Form 拉開差距的角度。

### CSS `n of S` Selector Enables Conditional Form Validation
### CSS `n of S` 選擇器解鎖純 CSS 條件式表單驗證

[原文連結](https://frontendmasters.com/blog/css-n-of-selectors-for-conditional-validation/)

- **The pattern**
  - `:nth-child(n of <selector-list>)` only counts siblings that match the given selector — not all siblings.
  - Combined with `:has()`, you can detect "the Nth filled-in field" purely in CSS.
- **Example**
  - ```css
    :nth-child(3 of .field:has(
      [type="email"]:not(:placeholder-shown),
      [type="radio"]:checked
    )) { /* triggers at the 3rd filled field */ }
    ```
- **Use case**
  - Unlock a submit button or show encouragement after the user fills N of M required fields, no JS needed.
-------
- **這個寫法**
  - `:nth-child(n of <selector-list>)` 只在符合該選擇器的 sibling 中算數，不是把所有 sibling 都算進去。
  - 配合 `:has()` 就可以純用 CSS 判斷「第 N 個被填好的欄位」。
- **範例**
  - ```css
    :nth-child(3 of .field:has(
      [type="email"]:not(:placeholder-shown),
      [type="radio"]:checked
    )) { /* 第 3 個被填好的欄位才會觸發 */ }
    ```
- **應用情境**
  - 使用者填完 M 個欄位中的 N 個時才解鎖送出按鈕、或顯示鼓勵訊息，完全不用 JS。

### Microsoft Edge Stores All Passwords in Memory in Cleartext
### Microsoft Edge 把所有密碼以明文留在記憶體中

[原文連結](https://news.ycombinator.com/item?id=43891231)

  - 提醒大家：瀏覽器儲存的密碼保護的是「靜態（at rest）」，不是「執行期（at runtime）」；專用密碼管理器會把不用的祕密重新鎖起來，安全性差距是真的有意義的。

## Glossary

- **Agent Skill**
  - A markdown-based, scoped workflow with explicit steps, checkpoints, and exit criteria that an AI agent loads on demand — distinct from a static reference doc.
  - 一份 markdown 寫的、有作用範圍的工作流，內含明確步驟、檢查點與結束條件，AI agent 在需要時才載入；不是靜態的參考文件。
- **MCP (Model Context Protocol)**
  - An open protocol that standardizes how LLM agents call external tools and data sources (n8n, Browserbase, GitHub, etc.).
  - 標準化 LLM agent 如何呼叫外部工具與資料來源（n8n、Browserbase、GitHub 等）的開放協議。
- **Anti-Rationalization Table**
  - A table inside an agent skill that pairs common shortcut excuses ("we can skip the test for now") with pre-written rebuttals — so the agent catches itself.
  - Agent skill 內建的對照表，左欄是常見的偷工藉口（「測試先跳過吧」），右欄是事先寫好的反駁；讓 agent 自己抓自己。
- **Headless Form Library**
  - A form library that supplies state, validation, and reactivity but no UI — you bring your own components and rendering.
  - 只提供狀態、驗證、響應式邏輯，不附 UI 的表單庫；元件與 render 由你自己出。
- **`:has()` Selector**
  - A CSS pseudo-class that matches an element if any of its descendants match the supplied selector — effectively a "parent selector".
  - CSS pseudo-class，當元素的某個子孫符合給定選擇器時就 match；本質上就是「父選擇器」。
- **`:nth-child(n of S)`**
  - The `of` syntax limits `:nth-child()` counting to siblings matching selector `S`, instead of counting every sibling.
  - `of` 語法讓 `:nth-child()` 只在符合 `S` 的 sibling 中計數，不是把所有 sibling 都算進去。
- **AST-Level Diff (ripper-tree diff)**
  - Verifying a code transformation by parsing source before and after and comparing the resulting syntax trees — guarantees semantic equivalence beyond what plain text diff can prove.
  - 驗證程式碼變形是否安全：把改動前後分別 parse 成 syntax tree 再比對，能保證語意等價，比純文字 diff 強得多。
- **Enshittification**
  - Cory Doctorow's term for the gradual degradation of a platform once it locks in users — restrictions, surprise fees, opaque policies — frequently invoked to flag early warning signs.
  - Cory Doctorow 提出的詞，指平台鎖住用戶後逐漸變爛的過程：限制變多、計費出乎意料、政策不透明；常被用來示警早期徵兆。
- **Dogfooding**
  - The practice of a product team using their own product internally to catch issues before customers do.
  - 產品團隊自己內部用自家產品，讓問題在使用者發現之前就先被抓出來的做法。
- **Plan Mode (Claude Code)**
  - A Claude Code mode (Shift+Tab) where the agent proposes changes and waits for explicit approval before editing files.
  - Claude Code 的一種模式（Shift+Tab 切換），agent 會先提出修改計畫，等到使用者明確同意後才動檔案。
