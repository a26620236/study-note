### Scott Moss: AI Engineer Is a New Role
### Scott Moss：「AI Engineer」是一個新角色

[原文連結](https://frontendmasters.com/blog/ai-engineer-is-a-new-role/)

- **The slogan**
  - "The agent is the easy part. The loop is the job." — getting an agent to work once is trivial; keeping it reliable in production is the actual discipline.
- **vs other roles**
  - ML engineers work at the model layer (training, datasets, optimisation); AI engineers work at the application layer (turning research into a usable product).
  - Software engineers optimise deterministic code paths; AI engineers must optimise a feedback loop on top of a non-deterministic system.
- **Four core skills**
  - RAG, evals, agents, production deployment.
- **Day-to-day work**
  - Context engineering (token budgets), tool design, evaluation, production reliability (self-healing, error handling, UX).
- **Defining loop**
  - Build → Eval → Improve → Eval → Improve — never "ship and forget".
-------
- **核心 slogan**
  - 「Agent 是容易的部分，loop 才是真正的工作。」 — 讓 agent 跑一次很容易；讓它在 production 持續穩定才是這個學科的本體。
- **與其他角色的差別**
  - ML 工程師在模型層（訓練、資料集、優化）；AI 工程師在應用層（把研究做成可用產品）。
  - 軟體工程師在確定性程式碼路徑上做優化；AI 工程師在非確定性系統之上優化回饋迴圈。
- **四個核心能力**
  - RAG、eval、agent、生產部署。
- **日常工作**
  - 上下文工程（token 預算）、工具設計、評估、生產可靠度（自我修復、錯誤處理、UX）。
- **這個職位的定義性 loop**
  - Build → Eval → Improve → Eval → Improve — 沒有「上線後就放著」這回事。

### What's in a GGUF (Besides the Weights) — and What's Still Missing
### GGUF 除了權重以外有什麼 — 又少了什麼

[原文連結](https://nobodywho.ooo/posts/whats-in-a-gguf/)

- **What's there**
  - Chat templates (Jinja2), special tokens (EOS etc.), recommended sampler config and sampler chain order — all in one file.
- **What's missing**
  - Tool-calling format: every model uses a different syntax → inference engines build per-model parsers.
  - Think tokens: no metadata to separate reasoning sections from output.
  - Projection models: multimodal (image/audio) still ships as separate files.
  - Feature flags: no standard way to declare supported capabilities → engines fall back to substring-matching the filename.
- **Why care**
  - Standardising these would let apps swap models without code changes — especially important on small models (≤1B) where type-safe tool calls prevent errors.
-------
- **已經有的**
  - Chat template（Jinja2）、特殊 token（如 EOS）、建議的 sampler 設定與 sampler 鏈順序 — 全部一檔搞定。
- **還缺的**
  - Tool-calling 格式：每個模型用不同語法 → 推理引擎得為每個模型寫 parser。
  - Think token：沒有 metadata 來分開推理段落與最終輸出。
  - 多模態 projection 模型：影像／音訊還是要另外開檔。
  - Feature flag：沒有標準方式宣告支援的能力 → 引擎用「比對檔名子字串」這種 hack。
- **為什麼要在意**
  - 補上這些之後，app 可以零修改換模型 — 對小模型（≤1B）特別重要，因為型別安全的 tool call 才能避免錯誤。

### Apple M5 上首個公開的 kernel 記憶體破壞 exploit

[原文連結](https://blog.calif.io/p/first-public-kernel-memory-corruption)

- **The exploit**
  - Data-only kernel local privilege escalation on bare-metal Apple M5; bypasses Memory Integrity Enforcement (MIE).
  - Combines two vulnerabilities with a side-channel against EMTE tags — converts probabilistic barriers into deterministic outcomes.
- **Significance**
  - MIE took ~5 years and billions of dollars to develop; this shows it can be defeated by memory-corruption exploits paired with AI-assisted vuln discovery.
- **Timeline**
  - Bugs found Apr 25; working exploit by May 1 (5 days); public disclosure May 14.
  - Affected: macOS 26.4.1 (25E253). No patch yet — researchers will publish their 55-page report after Apple ships a fix.
-------
- **Exploit**
  - 在裸機 Apple M5 上的「純資料層」kernel local privilege escalation；繞過 Memory Integrity Enforcement（MIE）。
  - 組合兩個漏洞加上對 EMTE tag 的旁路 — 把機率性的保護化為確定性繞過。
- **意義**
  - MIE 是花了約 5 年、數十億美元投入打造的保護；這證明它能被記憶體破壞 exploit 加上 AI 輔助的漏洞挖掘擊敗。
- **時程**
  - 4/25 找到漏洞；5/1 完成可用 exploit（5 天）；5/14 公開揭露。
  - 受影響：macOS 26.4.1（25E253）。尚無修補 — 研究者表示要等 Apple 出修補後才會釋出 55 頁完整報告。

### NGINX Rift (CVE-2026-42945): Critical RCE in `rewrite` Module Since 2008
### NGINX Rift（CVE-2026-42945）：`rewrite` 模組從 2008 年起就存在的重大 RCE

[原文連結](https://github.com/DepthFirstDisclosures/Nginx-Rift)

- **The bug**
  - Heap buffer overflow in NGINX's `rewrite` module: the length-calculation phase doesn't account for URI escaping done during the copy phase, letting attacker-controlled data overflow the buffer.
- **Severity**
  - Unauthenticated RCE on any server using `rewrite` and `set` directives.
  - Uses "heap feng shui" to corrupt an adjacent memory pool's cleanup pointer → arbitrary command execution on pool destruction.
- **Affected**
  - NGINX Open Source 0.6.27 – 1.30.0; NGINX Plus R32–R36. Bug has existed since 2008.
- **Patches**
  - OSS: 1.31.0 and 1.30.1.
  - Plus: R36 P4, R35 P2, R32 P6.
- **What to do**
  - Patch today; if you can't, audit configs for `rewrite`/`set` rules touching user-controlled URI components and consider rate-limiting / WAF rules.
-------
- **漏洞**
  - NGINX `rewrite` 模組的 heap buffer overflow：長度計算階段沒考慮複製階段做的 URI escaping，攻擊者可控資料因此可溢出 buffer。
- **嚴重度**
  - 對任何用 `rewrite` 與 `set` 指令的伺服器而言為未授權 RCE。
  - 利用「heap feng shui」破壞相鄰 memory pool 的 cleanup 指標 → pool 銷毀時執行任意指令。
- **受影響**
  - NGINX Open Source 0.6.27 – 1.30.0；NGINX Plus R32–R36。漏洞自 2008 年起就存在。
- **修補**
  - OSS：1.31.0 與 1.30.1。
  - Plus：R36 P4、R35 P2、R32 P6。
- **應對**
  - 今天就升級；無法升級者應稽核哪些 `rewrite`／`set` 規則接觸到使用者可控的 URI 片段，並考慮加上 rate-limit／WAF 規則。

## Glossary

- **Spec-Driven Development (SDD)**
  - A methodology where written specifications are the primary artefact and the implementation is generated from them — the inverse of the traditional "write code, then document it" flow.
  - 一種把「書面規格」當作主要產物、實作由規格生成的開發方法論 — 與傳統「先寫程式碼，事後補文件」的順序相反。
- **Eval (in AI engineering)**
  - A repeatable test that scores an agent or LLM's behaviour on a curated set of inputs — the equivalent of unit tests for non-deterministic systems.
  - 一個可重複執行的測試，會把 agent 或 LLM 在精選輸入下的行為打分 — 在非確定性系統中扮演 unit test 的角色。
- **RAG (Retrieval-Augmented Generation)**
  - The pattern of fetching relevant context from a search/database step and stuffing it into the LLM prompt before generation — improves factuality and lets models answer about private data.
  - 在生成前先用搜尋／資料庫步驟撈相關上下文塞進 prompt 的模式 — 提升事實性，並讓模型能回答關於私有資料的問題。
- **GGUF**
  - The single-file container format for open-weight LLMs popularised by llama.cpp — bundles weights, tokenizer, chat template, special tokens, and sampler hints.
  - llama.cpp 推廣的「單檔」LLM 容器格式 — 一起打包權重、tokenizer、chat template、特殊 token、sampler 提示。
- **MIE (Memory Integrity Enforcement, Apple)**
  - Apple's hardware-backed memory tagging feature designed to make memory-corruption exploits probabilistically infeasible — defeated today on M5.
  - Apple 的硬體層 memory tagging 機制，原本要讓記憶體破壞 exploit 在機率上不可行 — 今天在 M5 上被擊敗。
- **EMTE tag**
  - Enhanced Memory Tagging Extension tag — a small value attached to each memory allocation that pointers must match to use it; the M5 exploit side-channels these tags.
  - Enhanced Memory Tagging Extension 的 tag — 附在每一塊記憶體配置上的小值，指標必須匹配才能存取；M5 exploit 透過旁路攻擊這些 tag。
- **Heap feng shui**
  - A class of techniques where the attacker manipulates the heap allocator into placing chosen objects next to a vulnerable allocation — used in the NGINX Rift exploit.
  - 一類攻擊技巧：攻擊者操弄 heap 配置器，讓自己選擇的物件被放在脆弱 allocation 旁邊 — NGINX Rift exploit 就靠這個。
- **AI scribe (medical)**
  - A class of tools that listen to clinician-patient conversations and auto-generate clinical notes — the Ontario audit is the largest external evaluation of this category to date.
  - 一類工具：聽臨床醫師與病患的對話、自動生成病歷 — 安大略的稽核是目前對這類產品最大規模的外部評估。
- **Context engineering**
  - Designing what tokens go into the model's window — system prompt, retrieved context, tool definitions, prior turns — to maximise quality while staying within token budgets.
  - 設計進入模型上下文的 token 內容 — 系統 prompt、檢索得到的上下文、工具定義、過往輪次 — 在 token 預算內最大化品質。
