### Researcher: Claude Code Steganographically Marks Requests to Non-Standard Endpoints
### 研究者發現：Claude Code 會對非官方端點的請求做隱寫標記

[原文連結](https://thereallo.dev/blog/claude-code-prompt-steganography) · [HN 討論](https://news.ycombinator.com/item?id=48734373)

- **Core**
  - Inspecting the Claude Code binary, the author found a function that subtly alters the date string injected into the system prompt — visually normal text carrying hidden data via tiny, font-invisible character variations.
  - The marking appears to be triggered by the `ANTHROPIC_BASE_URL` environment variable (i.e. when routing through a non-standard/proxy endpoint), and can encode signals such as timezone.
  - Domain and keyword lists were stored base64-encoded and XOR-decoded with key `91`.
- **Impact**
  - Community reading is that this is anti-abuse fingerprinting — a way to detect when Claude Code traffic is being proxied or resold, rather than an attack on users.
  - Still a transparency concern: hidden markers in a tool you run locally are worth knowing about if you operate gateways or route Claude Code through custom endpoints.
- **Note**
  - This is a community/reverse-engineering finding, not an official disclosure; treat the exact mechanism as "as reported."
-------
- **核心**
  - 作者拆解 Claude Code 執行檔，發現有個函式會微幅改動注入 system prompt 的日期字串——表面看起來是正常文字，卻用字體上幾乎看不見的字元變化夾帶隱藏資料。
  - 這個標記似乎由 `ANTHROPIC_BASE_URL` 環境變數觸發（也就是走非官方／代理端點時），並可編碼時區等訊號。
  - 網域與關鍵字清單以 base64 儲存，再用金鑰 `91` 做 XOR 解碼。
- **影響**
  - 社群普遍認為這是防濫用的指紋機制——用來偵測 Claude Code 流量是否被代理或轉賣，而非針對使用者的攻擊。
  - 但仍是透明度上的疑慮：如果你在跑 gateway 或把 Claude Code 導向自訂端點，知道本地工具會夾帶隱藏標記是有意義的。
- **提醒**
  - 這是社群逆向工程的發現，並非官方揭露；文中機制細節請當作「據報如此」看待。

### Anthropic：我們如何跨產品圍堵 Claude（Claude Code 沙箱實戰教訓）

- **Core**
  - Three-layer defense: the model (system prompts, classifiers), the execution environment (sandboxes, VMs, egress controls), and external content access (tool permissions, data validation).
  - Claude Code uses OS-level sandboxes (Seatbelt on macOS, bubblewrap on Linux) with approval gates on the user's machine.
- **The uncomfortable data**
  - Users approve ~93% of permission prompts — approval fatigue makes dialogs a weak last line of defense.
  - Real incidents: phished employees injected exfiltration commands (24 of 25 attempts succeeded); network allowlists implicitly grant access to every API function they expose.
- **Takeaway**
  - Environmental boundaries matter as much as model alignment; battle-tested primitives (hypervisors, OS sandboxes) beat custom security code. Match isolation strength to user expertise.
-------
- **核心**
  - 三層防禦：模型層（system prompt、分類器）、執行環境層（沙箱、VM、出網控制），以及外部內容存取層（工具權限、資料驗證）。
  - Claude Code 在使用者機器上用 OS 級沙箱（macOS 的 Seatbelt、Linux 的 bubblewrap）搭配權限核准關卡。
- **令人不安的數據**
  - 使用者對權限提示的核准率約 93%——核准疲勞讓彈窗成為很脆弱的最後防線。
  - 真實事件：被釣魚的員工注入外洩指令（25 次嘗試中 24 次成功）；網路白名單會隱性授予它所開放的每個 API 功能。
- **重點**
  - 環境邊界跟模型對齊一樣重要；久經考驗的基礎元件（hypervisor、OS 沙箱）勝過自製安全程式碼。隔離強度要對應使用者的專業程度。

### Your Database's Isolation Levels Don't Mean What You Think
### 你的資料庫隔離等級跟你想的不一樣

[原文連結](https://frontendmasters.com/blog/your-databases-isolation-levels-dont-mean-what-you-think/)

- **Core**
  - The SQL standard's isolation-level names (Read Committed, Repeatable Read, Serializable) map to very different real guarantees across Postgres, MySQL/InnoDB, and others.
  - "Repeatable Read" in one engine is not the same anomaly-prevention as in another; the same label can hide different behaviors.
- **Takeaway**
  - Don't reason from the level name — check what your specific engine actually prevents (dirty reads, non-repeatable reads, phantoms, write skew) before relying on it for correctness.
-------
- **核心**
  - SQL 標準的隔離等級名稱（Read Committed、Repeatable Read、Serializable）在 Postgres、MySQL/InnoDB 等不同引擎上，對應到差很多的實際保證。
  - 同樣叫「Repeatable Read」，在不同引擎防的異常並不一樣；同一個標籤可能藏著不同行為。
- **重點**
  - 別只看等級名稱推理——在拿它保證正確性之前，先確認你這顆引擎實際防住了哪些異常（dirty read、non-repeatable read、phantom、write skew）。

## Glossary

- **Steganography**
  - Hiding data inside otherwise-normal content (here, invisible character tweaks in text) so it's unnoticeable to a casual reader.
  - 把資料藏進看似正常的內容中（此處是文字裡看不見的字元微調），讓一般讀者不會察覺。
- **ANTHROPIC_BASE_URL**
  - An environment variable that points Claude Code at a specific API endpoint; setting it to a non-official URL routes traffic through a proxy or gateway.
  - 一個環境變數，用來指定 Claude Code 連的 API 端點；設成非官方 URL 就會把流量導向代理或 gateway。
- **Tokenizer**
  - The component that splits text into tokens; a different tokenizer can change how many tokens the same text costs, affecting price and context limits.
  - 把文字切成 token 的元件；換 tokenizer 會改變同樣文字所耗的 token 數，進而影響費用與 context 上限。
- **Egress control**
  - Restricting what outbound network connections a sandboxed process may make, to limit data exfiltration.
  - 限制沙箱程序能發出哪些對外網路連線，用來降低資料外洩風險。
- **Prompt injection**
  - An attack where malicious text in tool input or fetched content hijacks an agent's instructions.
  - 一種攻擊：工具輸入或抓取到的內容裡的惡意文字，劫持了 agent 的指令。
- **Isolation level**
  - A database setting that controls which concurrency anomalies (dirty/non-repeatable/phantom reads, write skew) transactions are protected from.
  - 資料庫設定，決定交易能被保護、避免哪些併發異常（dirty／non-repeatable／phantom read、write skew）。
- **CNI (Container Network Interface)**
  - A standard for wiring up networking for containers/pods (assigning IPs, routing) in Kubernetes.
  - 一套標準，負責在 Kubernetes 中替容器／pod 接上網路（分配 IP、設定路由）。
- **Edge function**
  - Server-side code that runs on distributed points-of-presence close to users (e.g. Cloudflare Workers), rather than one central server.
  - 在靠近使用者的分散節點上執行的伺服器端程式碼（如 Cloudflare Workers），而非集中在單一伺服器。
