### Anthropic: How We Contain Claude Across Products
### Anthropic：我們如何在各產品中圍堵 Claude

[原文連結](https://www.anthropic.com/engineering/how-we-contain-claude)

- **The thesis**
  - Capability and blast radius rise together. Probabilistic model-layer defences alone can't be reliable — deterministic boundaries (sandboxes, VMs, network rules) must anchor the design.
- **Per-product containment**
  - **Claude.ai**: code runs in ephemeral gVisor containers on Anthropic infra; threat model is tenant isolation, not protecting the user's machine.
  - **Claude Code**: runs on user's host. Was approval-fatigued (users approved ~93% of prompts). Now combines OS sandbox (Seatbelt on macOS, bubblewrap on Linux) with an auto-mode classifier that catches ~83% of overeager actions — cuts permission dialogs **84%**.
  - **Claude Cowork**: full VMs (Apple Virtualization on macOS, HCS on Windows) for non-technical users. MITM proxy inside the VM intercepts API calls and rejects attacker-supplied credentials.
- **Honest disclosures**
  - In red-team tests: direct prompt injection via phishing exfiltrated data in **24 of 25** attempts.
  - Project config can execute *before* the trust prompt; EDR can't see inside VMs.
- **Available to use**
  - Sandbox runtime is open-sourced. Enterprise MDM controls mount-path allowlists. OTLP event exports give pull-based logging for EDR pipelines.
-------
- **核心論點**
  - 能力與「炸傷範圍」一起放大。光靠模型層那種「機率性」的防護不可能可靠 — 設計必須奠基在「決定性的邊界」上（沙盒、VM、網路規則）。
- **每個產品的圍堵方式**
  - **Claude.ai**：程式碼跑在 Anthropic 基礎設施上的 ephemeral gVisor container；威脅模型是租戶隔離，不是保護使用者的電腦。
  - **Claude Code**：跑在使用者本機。原本「approval 疲勞」嚴重（使用者大約 93% 都按 approve）。現在 OS 沙盒（macOS 的 Seatbelt、Linux 的 bubblewrap）配 auto-mode classifier，可攔下約 83% 的越權動作 — 權限對話框少了 **84%**。
  - **Claude Cowork**：給非技術使用者用整台 VM（macOS 的 Apple Virtualization、Windows 的 HCS）。VM 內部的 MITM proxy 攔截 API 呼叫，拒絕由攻擊者提供的憑證。
- **誠實揭露的破口**
  - red team 測試：透過釣魚直接 prompt injection，**25 次裡 24 次**成功外洩資料。
  - 專案層級的設定有可能在「信任提示」跳出**之前**就執行了；EDR 看不見 VM 內部活動。
- **可直接使用的成果**
  - 沙盒 runtime 已開源。企業可透過 MDM 控制 mount 路徑白名單。OTLP 事件匯出讓 EDR pipeline 能 pull-based 拉日誌。

### Builder.io: Designing Generative UI in an Agent-Native World
### Builder.io：在 agent-native 世界中設計 Generative UI

[原文連結](https://www.builder.io/blog/designing-generative-ui-in-an-agent-native-world)

- **The reframe**
  - Generative UI ≠ "AI writes JSX at runtime". That path is slow and fragile. The right model is **text-to-hydration**: AI *arranges* prebuilt elastic primitives and pipes data into them.
- **Elastic primitives**
  - Designers ship a "kit of parts" (metric cards, tables, audio players) with explicit auto-layout, spacing constraints, and spatial guardrails — the AI's job is composition, not invention.
- **Machine-readable design rules**
  - Replace casual prose with structured metadata.
  - Encode constraints directly on the component: "collapse if compression exceeds X", "only show analytics charts when ≥3 streams compared".
  - Edit the primitive once → cascades across thousands of agent-generated screens.
- **Unified human/agent surface**
  - Every clickable thing maps to an agent-callable tool. Humans and agents share one database / action model — the agent doesn't have to invent UI for what already exists.
-------
- **重新框定**
  - Generative UI ≠「AI 在 runtime 寫 JSX」。那條路慢又脆。正確的模型是 **text-to-hydration**：AI「排列」預先做好的彈性元件並餵資料給它們。
- **彈性元件**
  - 設計師交付的是一組「零件包」（指標卡片、表格、音訊播放器），帶著明確的 auto-layout、間距限制與空間護欄 — AI 只負責組合，不負責發明。
- **機器可讀的設計規則**
  - 用結構化的 metadata 取代隨筆式的設計文字。
  - 把限制直接編碼在元件上：「壓縮超過 X 就 collapse」、「比較 3 條以上資料流才秀分析圖表」。
  - 改一次元件 → 在 agent 產出的數千張畫面上全部跟著變。
- **人與 agent 共用同一個介面**
  - 每個可點擊的東西都對應到一個 agent 可呼叫的 tool。人和 agent 共享同一份 database／action model — agent 不需要再為「已經存在的東西」發明 UI。

### `claude-mem`: Persistent Memory Across Claude Code Sessions
### `claude-mem`：跨 Claude Code session 的持久記憶體

[GitHub 連結](https://github.com/thedotmack/claude-mem)

- **How it captures**
  - Five lifecycle hooks — SessionStart, UserPromptSubmit, PostToolUse, Stop, SessionEnd — quietly observe tool usage and AI-summarise into semantic snapshots.
- **How it recalls**
  - Three-layer progressive disclosure: compact search hits (~50–100 tokens) → timeline context → on-demand observation fetch (~500–1000 tokens each). Claims ~10× token saving over naive context dumping.
- **Stack**
  - Chroma for vector search + SQLite FTS5 for keyword; MCP tools for natural-language queries; web viewer at `localhost:37777`.
- **Install**
  - `npx claude-mem install`. Configure under `~/.claude-mem/settings.json` (model, port, language mode).
- **License**: Apache 2.0 — explicitly chosen so it can be embedded in commercial dev tools and agents.
-------
- **怎麼存**
  - 五個生命週期 hook — SessionStart、UserPromptSubmit、PostToolUse、Stop、SessionEnd — 默默觀察 tool 使用，再用 AI 摘要為語意快照。
- **怎麼讀回來**
  - 三層 progressive disclosure：壓縮搜尋命中（~50–100 tokens）→ 時序上下文 → 按需拉取觀察細節（每筆 ~500–1000 tokens）。號稱比「整包丟進 context」省 ~10 倍 token。
- **技術棧**
  - 向量檢索用 Chroma、關鍵字用 SQLite FTS5；提供 MCP tool 接自然語言查詢；附 `localhost:37777` 的網頁檢視器。
- **安裝**
  - `npx claude-mem install`。設定檔在 `~/.claude-mem/settings.json`（可調模型、port、語言模式）。
- **授權**：Apache 2.0 — 作者特別說明選這條是為了讓它可被嵌入到商業開發工具、agent 之中。

### `stop-slop` + `taste-skill`: The "Anti-Slop" Skill Genre
### `stop-slop` + `taste-skill`：「反 AI slop」的 skill 流派

- **`stop-slop` — for prose**
  - Strips characteristic AI tells: throat-clearing openers ("In today's world…"), emphasis crutches, business jargon, vague declaratives, dramatic em-dashes, staccato fragmentation, passive voice.
  - Hard rules in SKILL.md; copy into Claude Code, Claude Projects, or any system prompt.
- **`taste-skill` — for UI**
  - Three dials: `DESIGN_VARIANCE` (1–10: centered/clean → asymmetric/modern), `MOTION_INTENSITY`, `VISUAL_DENSITY`.
  - "Hard em-dash ban", "redesign-audit protocol", "strict pre-flight check" — explicit anti-repetition rules.
  - Install: `npx skills add https://github.com/Leonxlnx/taste-skill`.
- **Why this matters**
  - First sign of a "skill genre": both repos solve the same problem (machine-recognisable AI output) for different surfaces (prose vs. UI). Treat them as a pattern, not one-off tools.
-------
- **`stop-slop` — 給 prose 用**
  - 剝除 AI 寫作的固定特徵：清嗓開頭（「在當今世界…」）、過度強調的副詞、business 行話、含糊的斷言、戲劇化的破折號、刻意短句、被動語態。
  - SKILL.md 內含硬規則；可直接放進 Claude Code、Claude Projects 或任何 system prompt。
- **`taste-skill` — 給 UI 用**
  - 三個旋鈕：`DESIGN_VARIANCE`（1–10：置中乾淨 → 不對稱現代風）、`MOTION_INTENSITY`、`VISUAL_DENSITY`。
  - 「禁用 em-dash」、「redesign-audit 流程」、「嚴格的 pre-flight check」 — 明確的反重複規則。
  - 安裝：`npx skills add https://github.com/Leonxlnx/taste-skill`。
- **為什麼值得記錄**
  - 「skill 流派」首次成形：兩個 repo 解的是同一個問題（AI 輸出可被一眼看穿）的兩個面向（文字 vs. UI）。建議當成一種設計模式來看，不是個別工具。

### Frontend Masters: The Production Playbook for Node.js Stream Leaks
### Frontend Masters：Node.js stream 洩漏的生產守則

[原文連結](https://frontendmasters.com/blog/the-production-playbook-for-node-js-stream-leaks/)

- **The five rules**
  - Use `pipeline()` from `node:stream/promises`, not `.pipe()`.
  - Respect the boolean return of `.write()` — await `drain` if it returns `false`.
  - Destroy what you create — use `AbortController` to tear down explicitly.
  - Profile before production — constrain heap and inspect `WritableState` in DevTools.
  - Test backpressure — assert producers actually pause under pressure.
- **Why `pipeline()`**
  - `.pipe()` only fires teardown on the `finish` event — which never fires on a dropped connection. `pipeline()` detects `ERR_STREAM_PREMATURE_CLOSE` and destroys upstream resources.
- **Code pattern**
  - ```js
    import { pipeline } from "node:stream/promises";
    await pipeline(db.cursor(), csvTransform, res);
    ```
- **Diagnostic tip**
  - Watch `stream.writableLength` live: if it's bounded by `highWaterMark` you're fine; if it climbs without bound, the producer is ignoring backpressure.
- **Five common failure modes**
  - Client disconnects, server keeps querying DB. Manual listeners block exit. Timeout fires but upstream continues. DB connections held open during slow downloads. Source pushes chunks after `pipeline()` errors.
-------
- **五條規則**
  - 用 `node:stream/promises` 的 `pipeline()`，別用 `.pipe()`。
  - 認真對待 `.write()` 的 boolean 回傳值 — 拿到 `false` 就 await `drain`。
  - 自己建的東西自己拆 — 用 `AbortController` 明確 tear down。
  - 上線前壓測 — 限制 heap，在 DevTools 裡看 `WritableState`。
  - 測 backpressure — 寫單元測試確認 producer 真的會在壓力下停下來。
- **為什麼 `pipeline()`**
  - `.pipe()` 只在 `finish` 事件觸發時清理 — 但連線被斷掉時根本不會觸發 finish。`pipeline()` 會偵測 `ERR_STREAM_PREMATURE_CLOSE` 並把上游資源砍掉。
- **程式碼樣板**
  - ```js
    import { pipeline } from "node:stream/promises";
    await pipeline(db.cursor(), csvTransform, res);
    ```
- **診斷小技巧**
  - 即時觀察 `stream.writableLength`：如果有界（受 `highWaterMark` 限制）就 OK；如果一路漲，代表 producer 沒在做 backpressure。
- **五個常見出包場景**
  - client 中斷連線，server 還在打 DB query。手動加的 listener 卡住程序退出。timeout 觸發但上游沒停。慢下載期間 DB 連線一直開著。`pipeline()` 出錯後 source 還在推 chunk。

### React Server Components in TanStack Start
### TanStack Start 裡的 React Server Components

[原文連結](https://frontendmasters.com/blog/react-server-components-in-tanstack/)

- **The pitch**
  - Author Adam Rackis calls TanStack's RSC implementation "radically different, and in my opinion, better" than Next.js — the key word is **explicit**.
- **The API**
  - `createServerFn({ method: "GET" }).handler(...)` defines an RSC entry point.
  - `createCompositeComponent((props) => ...)` returns an RSC that accepts props from the client.
  - Props passed in are automatically client components — no `"use client"` pragma needed.
- **Example**
  - ```ts
    const getAppShell = createServerFn({ method: "GET" }).handler(async () => {
      return createCompositeComponent((props) =>
        <ApplicationShell {...props} />
      );
    });
    ```
  - Render with `<CompositeComponent src={appShell} HeaderContent={Component}>`.
- **Caveats**
  - RSCs **can't receive new props from client code** after they've run server-side.
  - Only worth it for large/heavy trees with little interactivity — not a data-fetching shortcut (TanStack loaders already cover that).
  - Real example: 308KB → 203KB bundle reduction.
-------
- **賣點**
  - 作者 Adam Rackis 認為 TanStack 的 RSC 實作「根本性地比 Next.js 好」 — 關鍵字是「**顯式**」。
- **API**
  - `createServerFn({ method: "GET" }).handler(...)` 定義 RSC 入口。
  - `createCompositeComponent((props) => ...)` 回傳一個能接受 client props 的 RSC。
  - 傳進去的 props 會自動是 client component — 不用寫 `"use client"`。
- **範例**
  - ```ts
    const getAppShell = createServerFn({ method: "GET" }).handler(async () => {
      return createCompositeComponent((props) =>
        <ApplicationShell {...props} />
      );
    });
    ```
  - 使用：`<CompositeComponent src={appShell} HeaderContent={Component}>`。
- **適用條件**
  - RSC 在 server 跑過之後，**沒辦法**再從 client 收到新的 props。
  - 只在「樹大、互動少」時才划算 — 不是拿來偷懶做 data fetching（TanStack loader 已經處理那塊）。
  - 實例：bundle 從 308KB 降到 203KB。

## Glossary

- **gVisor**
  - A user-space kernel from Google that intercepts syscalls before they reach the host kernel — used to sandbox untrusted code with much lower overhead than a VM.
  - Google 出的 user-space kernel，會在 syscall 抵達主機 kernel 前攔下來 — 用於沙盒化不可信程式碼，開銷比 VM 小得多。
- **Seatbelt / bubblewrap**
  - macOS's Seatbelt (`sandbox-exec`) and Linux's bubblewrap are OS-level sandboxes that restrict file, network, and process access without spinning up a VM.
  - macOS 的 Seatbelt（`sandbox-exec`）與 Linux 的 bubblewrap 是 OS 層級沙盒，不用開 VM 就能限制檔案、網路、process 存取。
- **Auto-mode classifier (Claude Code)**
  - A model-based gate that decides whether to skip a permission prompt — Anthropic reports ~83% catch rate on overeager actions while cutting dialogs 84%.
  - 一個模型驅動的閘門，決定要不要跳出權限確認 — Anthropic 報告攔下大約 83% 的越權動作，同時把對話框數量砍掉 84%。
- **Generative UI**
  - Interfaces assembled at runtime by AI instead of served from fixed templates. The Builder.io article argues the right form is *hydration* (arranging pre-built parts), not *generation* (writing JSX from scratch).
  - 由 AI 在 runtime 組裝的介面，而非靜態樣板。Builder.io 主張正確的形式是「hydration」（排列預製零件），而不是「generation」（從零寫 JSX）。
- **Elastic primitive**
  - A composable UI component built with explicit layout / spacing / state constraints, designed to be safely arranged by an AI rather than hand-customised in each layout.
  - 一個帶著明確 layout／間距／狀態限制的可組合 UI 元件，設計目的就是讓 AI 可以安全地組合，而不是每個畫面手動微調。
- **Text-to-hydration**
  - Builder.io's term for the architecture where a prompt selects and arranges existing components rather than asking the model to emit new JSX/markup each render.
  - Builder.io 用來指「prompt 從既有元件挑選與排列」的架構，而不是叫模型每次 render 都生新 JSX／markup。
- **AgentShield**
  - The security layer in `ECC` — a rule pack and test harness scanning for prompt injection, secrets, and configuration mistakes in an agent environment.
  - `ECC` 的安全層 — 一組規則包與測試 harness，掃 agent 環境裡的 prompt injection、洩漏的 secret、設定錯誤。
- **Instincts (ECC)**
  - Patterns auto-extracted from prior agent sessions, confidence-scored, and clustered into reusable skills — a feedback loop turning ephemeral runs into durable knowledge.
  - 從過往 agent session 自動抽出的模式，被打信心分後再分群成可重用的 skill — 一個把「一次性運行」轉成「持久知識」的回饋迴路。
- **`pipeline()` (Node)**
  - The modern replacement for `.pipe()`, exported from `node:stream/promises`. Detects premature stream close and tears down the whole chain — `.pipe()` doesn't.
  - `.pipe()` 的現代替代品，從 `node:stream/promises` 匯入。會偵測 stream 被提前關閉並拆掉整條鏈 — `.pipe()` 不會。
- **Composite Component (TanStack)**
  - TanStack Start's primitive for declaring an RSC that accepts client-side child components as props, slotted in after the server pass.
  - TanStack Start 用來宣告 RSC 的原語：可接收 client 端的子元件當作 props，在 server pass 之後被 slot 進去。
- **Build-eval-improve loop**
  - Scott Moss's framing of the AI engineer's job: build the agent, evaluate failures, find root causes, fix, re-evaluate — indefinitely.
  - Scott Moss 對 AI engineer 工作的定義：把 agent 蓋起來、評估失敗、找根因、修、再評估 — 持續循環，沒有終點。
- **On-device MCP**
  - Running MCP tool selection inside an on-device LLM (e.g. Gemma 4 on Android), so prompts and decisions never leave the device — only structured tool calls go to the network.
  - 在裝置端 LLM（例如 Android 上的 Gemma 4）內執行 MCP tool 選擇，prompt 與決策從未離開裝置 — 只有結構化的 tool call 會走網路。
